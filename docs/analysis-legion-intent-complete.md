# LEGION — полный разбор замысла: каждая рекомендация фактом, без заглушек и без «потом»

Снимок: `c213041`. Код и прошивку этот документ не меняет.

Путь «нашёл → SDR → усилитель за микросекунды» (форумы Nuand, FIR, бюджет
гейта): [analysis-legion-us-path.md](analysis-legion-us-path.md).
Уточнение «нашлась 2450 → на усилитель 2445…2455»:
[analysis-legion-look-window.md](analysis-legion-look-window.md).

Предыдущий разбор (`analysis-legion-recheck.md`) откладывал железо, timing
xA4, физические 400 мкс и «частоту внутри окна». Это противоречит требованию
полноценной рабочей системы. Здесь **закрытое определение замысла** и
**полный обязательный перечень**. Пункт либо входит в готовую систему и
имеет критерий приёмки, либо замыслом не обещан и это доказано текстом
продукта — не «оставим на потом».

**Вердикт.** На `c213041` полноценной системы по замыслу нет. Зелёные
хост/NIOS/GHDL тесты систему не закрывают: они допускают ложный успех и не
видят RF. Рабочая система = исправленное управление + фактически
применённые RF-параметры + собранный и сверенный образ + стенд, который
доказывает TX/LO/выдержку/гашение. Пропустить стенд нельзя: сам репозиторий
пишет, что без E1–E6 на целевой плате система стабильной не считается
(`README.md`, `fpga/README.md`). Текущие E1–E6 для замысла тоже недостаточны.

## 1. Замысел — закрытое определение (из текстов продукта, не из догадки)

Источник истины по «Автоматическому перехвату» — не маркетинговая фраза
«нашёл частоту», а согласованные формулировки в одном снимке.

**Хозяин и USB.** После Старта хозяин один — SDR. USB не в круге
«увидел → усилитель»: IQ на хост не гоняется
(`docs/architecture.md` 98–104, `fpga/README.md` 6–14,
`startOnboardIntercept` в `app/src/state/store.ts` 1038–1040).

**Что плата «находит».** Взгляд = аналоговый фильтр = шаг сетки LO.
«Нашёл взгляд — держал выдержку — шагнул дальше. Две частоты ближе ширины
взгляда — одно TX-окно; уже взгляд — 2450 и 2465 МГц как разные стоянки»
(`StartGate.tsx` 235–240). То же в `planOnboardIntercept`
(`fpgaFastpath.ts` 267–271, 339–341).

**Следствие, которое замыкает «частоту внутри окна».** Замысел обещает
ретрансляцию **всего взгляда**, центр которого — стоянка сетки
`planCenters`. Он **не** обещает измерить герцы тона внутри фильтра.
Это не пробел и не этап «потом»: USB в круге обнаружения запрещён, а
бортовой датчик — средняя \(I^2+Q^2\) (`legion_detector.vhd`), не FFT.
Точная частота внутри окна потребовала бы либо IQ на хост (запрещено
замыслом), либо новый FFT/CORDIC в FPGA (другой продукт). Для рабочей
системы по **этому** замыслу «найденная частота» = `AIR_FREQ` текущей
стоянки. Хост уже читает её в `status.freq_mhz` (`store.ts` 3001–3003).

**Два времени — разные величины.** Их нельзя подменять друг другом.

| Имя в UI | Что это в коде | Что это на SMA |
|---|---|---|
| Гейт / окно детектора | 2^shift валидных сэмплов, дефолт shift=4 → 16; `16/fs` | Как быстро гейт **может** открыть TX после появления энергии в уже выбранном взгляде. При 2 MSPS = 8 мкс; при 520834 Гц ≈ 30.7 мкс |
| Выдержка TURN | `SCAN_DWELL_US`, якорь = первый `det_active` (`legion_cmds.c` 564–578) | Как долго **держать LO на этом взгляде**, затем шаг. Пока энергия есть, mux держит TX (`lb_gated`). 400 мкс — удержание стоянки, не длина импульса «открыл и закрыл» |
| Тишина PRIORITY | 5 мс сэмплов tamer (`LEGION_SCAN_QUIET_MS`) | Когда шагать, если энергии нет |

Текст UI «держать усилитель на найденной частоте» (`StartGate.tsx` 248)
в коде = держать **взгляд/LO**. Усилитель открыт, пока `det_active` и ARM
живы. Это следует из mux (`legion_tx_mux.vhd` 88–94, 118+) и walker.

**Одно окно (коридор ≤ взгляд).** `planOnboardIntercept` при
`centers.length == 1`: «LO не шагает, гейт N µs» (`fpgaFastpath.ts` 339–341).
`legion_scan_walk` при `n == 1` возвращается сразу (`legion_cmds.c` 541–545).
Это **одно и то же правило**. Выдержка TURN для одной стоянки не шагает
и не гасит TX. Гашение — спад энергии, Стоп, watchdog. Перепроверка
«через секунду ARM жив» для n=1 **не дефект**: замысел требует, чтобы
ARM жил до Стопа. Дефект был бы, если при n>1 после dwell LO не шагнул.

**50 Ом.** Старт отказывает без `sdrLoadOk` (`store.ts` 1067–1069,
`planOnboardIntercept` 329–331). Это галочка оператора, не измерение.
Рабочая система на стенде обязана идти в нагрузку 50 Ом и **измерить**
выход. Модель PA в репозитории отсутствует — приёмка меряет факт, не
модель.

**Два тракта не смешивать.** SDR/FPGA и ESP32/ADF4351 запрещены вместе
(`architecture.md` 71–76, `store.ts` 1049–1050). Полноценная система —
оба тракта порознь, не один гибрид.

**Старый USB-handoff.** «FPGA+сканер с USB-handoff убран из Старта»
(`architecture.md` 113–116). Функция `fpgaHandoff` оставлена, потому что
«тесты читают ping-до-park по исходнику» (`store.ts` 1432–1434). При
вызове она ставит `fpgaAutoCycle: true` (1410–1413), и тогда хост сам
снимает ARM по выдержке/`det_count` (3040–3070) — USB снова в круге.
Для системы по замыслу этот путь обязан быть недостижим из Старта и из
любого UI. Оставить «для тестов» как живой код — дыра.

## 2. Обязательный перечень рабочей системы

Ниже нет фазы «можно не делать». Порядок — зависимость, не отсрочка.

### 2.1 Целостность управления (без этого TX может остаться под током)

| # | Факт в снимке | Почему без этого системы нет | Приёмка (обязана покраснеть на старом коде) |
|---|---|---|---|
| U1 | ARM: `_air_enable` → затем `_program_scan`; отказ «нет F1/F2» не откатывает эфир (`legion_gateway.py` 753–758, 547–548) | Отказной Старт оставляет RX+TX. Тест ловит только `ok:false` (`test_legion_fpga.py` 1125–1127) | После ARM с `scan_enable` без границ: протокол чтения `AIR_PREP` = down, флаги владения сняты, RFIC STANDBY (журнал команд, не словарь записей) |
| U2 | `legion_air_is_up` ставится в конце; частичный RX+отказ TX → `air_down` no-op `true` (`legion_cmds.c` 198, 221–223) | RX (и частично TX) остаются | Стаб RFIC: ENABLE RX ok, ENABLE TX fail → `air_up` false **и** ушёл STANDBY; повторный down не silent-success |
| U3 | DISARM вызывает `air_down()` без проверки (`legion_cmds.c` 659–662), шлюз считает CTRL=0 успехом | Неподтверждённое выключение = «ok» | Стаб: STANDBY fail → write CTRL и `op disarm` не ok; хост показывает unknown; повторный DISARM снова шлёт STANDBY |
| U4 | Отказ TX FREQUENCY: unmute и разные LO (`legion_cmds.c` 429–435) | Усилитель на чужой частоте | Стаб: RX freq ok, TX freq fail → mute остаётся 1, RX откатан или состояние unknown; unmute=0 запрещён |
| U5 | Чтение SCAN_* = STATUS (`legion_cmds.c` 696). FakeTransport так же (327–348). Тесты смотрят `._t.regs` | Нельзя проверить, что коридор/выдержка на плате те, что задал оператор | `read` SCAN_F1/F2/CTRL/DWELL по 0x80 = последние успешные записи. Словарь модели не оракул |
| U6 | `op set scan_dwell_ms` → тот же регистр мкс, `int(value)` (`legion_gateway.py` 871–884). `int(0.4)=0`. NIOS: 0 → дефолт 3e6 мкс (`legion_cmds.h` 44, `legion_cmds.c` 554) | Оператор «0,4 мс» получает 3 с удержания | `set scan_dwell_ms 0.4` → регистр 400; `0,4` и нечисло — отказ, не успех |
| U7 | UI: `parseFloat("0,4")===0` → `fpgaTurnDwellClamp(0)=3000` (`fpgaFastpath.ts` 70–73, `store.ts` 1083) | Запятая → 3 с, не 0.4 | Поле «0,4» и «0.4» дают 400 мкс на проводе; иначе отказ до ARM |

Пока U1–U7 красные, Старт/Стоп врать о тракте. Это не косметика.

### 2.2 Фактически применённые fs / BW / FIR (без этого взгляд не тот)

**Факт Nuand.** `bladerf2_sample_rate_range_4x` = 520834…2083334 Гц
(`bladerf2_common.h` 534–538). Host `bladerf2_set_sample_rate` для этого
диапазона включает RX FIR DEC4 и TX FIR INT4 **до** записи rate
([bladerf2.c:1093–1118](https://github.com/Nuand/bladeRF/blob/35174c30b009cdb335800c411f3c14d45283f12b/host/libraries/libbladeRF/src/board/bladerf2/bladerf2.c#L1093)).

**Факт Legion.** `airFsHz(0.2)=520834`, `airFsHz(2)=2000000`
(`fpgaFastpath.ts` 96–99). Оба значения **внутри** range_4x.
`legion_air_up` пишет SAMPLERATE и BANDWIDTH, не FILTER
(`legion_cmds.c` 124–174). INIT сам ставит FIR **DEFAULT** = RX DEC1 /
TX BYPASS (`devices_rfic_cmds.c` 178–181; `bladeRF2.h` 182, 196), затем
Legion перезаписывает rate поверх.

**Факт эталона в дереве.** foxhunt: FILTER DEC4/INT4, **потом** SAMPLERATE
768000 (`foxhunt/src/main.c` 234–246). Команда FILTER в том же NIOS RFIC
уже есть.

**Факт асимметрии.** Хост-park читает getSampleRate/getBandwidth и
отказывает при расхождении (`sdr_worker.py` 1278–1362). NIOS после
закрытия USB на micro **заново** пишет rate без readback фактического
(`legion_cmds.c` 130–132, 688–690 читает только статику «что просили»).
Walker считает quiet/dwell от этой статики (`legion_cmds.c` 550–556).
Если чип отклонил 520834 или держит другой fs — выдержка 400 мкс
считывается не в тех секундах.

**x40.** Каталог: фильтры LMS 1.5–28 МГц (`catalog.ts` 17). Комментарий
хоста: «x40 ниже 1.5 МГц откажет честно в park» (`fpgaFastpath.ts` 85).
Окно 0.2 МГц на x40 **не является** рабочим режимом этого чипа. На micro
0.2 МГц законен по BW min 200 кГц, но только вместе с FIR 4x.

| # | Обязанность | Приёмка |
|---|---|---|
| R1 | Перед SAMPLERATE, если fs∈[520834, 2083334]: FILTER RX DEC4 + TX INT4; иначе вернуть default. Порядок как у Nuand/foxhunt | Журнал RFIC: FILTER до SAMPLERATE; на 2e6 и 520834 — DEC4/INT4 |
| R2 | Readback SAMPLERATE, BANDWIDTH, FILTER после записи; отказ если факт ≠ запрос (допуск как park: fs 15%, BW не «1.5 вместо окна») | Стаб/железо: подмена actual → AIR_PREP отказ, тракт не unmute |
| R3 | Walker и WD_LIMIT считают от **прочитанного** fs, не от запрошенного | Тест: actual 2e6 при запросе 520834 → отказ, не «тихо 2e6 и dwell от 520834» |
| R4 | UI/план: x40 look < 1.5 МГц — отказ до park; micro 0.2 МГц — только после R1+R2 | Нельзя выбрать 0.2 на x40 и получить ARM |
| R5 | Дефолтный park 2 МГц тоже в зоне 4x — не исключение | Тот же тест, что R1, на 2000000 |

Без R1–R5 «взгляд 0.2 / 2 МГц» — запись в регистр, не настроенный канал.
Объявлять 0.2 МГц невозможным после этих пунктов нельзя, пока стенд не
измерил. Объявлять рабочим до R1–R2+стенда — тоже нельзя. Это не отсрочка:
стенд входит в тот же перечень (§2.6).

### 2.3 Единицы времени, watchdog, часы

| # | Факт | Обязанность | Приёмка |
|---|---|---|---|
| T1 | `WD_LIMIT` = round(tx_clk/65536), micro `tx_clk=fs` (`legion_fpga.py` 70–76). 520834 → 8 → ≈1.01 с; 2e6 micro → 31 → ≈1.02 с. Без `fs_hz` шлюз пишет дефолт 61 (`gateway.py` 737–741) | Всегда писать limit от фактического fs | ARM 520834 на micro: регистр 8, не 61; kick 500 мс не сжигает ARM |
| T2 | Heartbeat: toggle NIOS → 2 FF → фронт (`legion_regs.vhd` 137–155). Это уже CDC строба | Не заменять на ADI `sync_event` без доказательства дыры | GHDL уже бьёт expiry/kick. На стенде E5: wd_fired после потери kick, TX нули |
| T3 | `det_count` с rx в status без синхронизатора; на micro часы совпадают, на x40 нет (`legion_regs.vhd` 157–163) | На x40 — безопасный CDC (gray/handshake) **или** доказательство, что хост смотрит только стагнацию равных чтений (`detCountStagnant`, 1.2 с) и разрыв меняющегося счётчика не даёт ложный «gone» | HDL-тест двух доменов: ложный stagnation не возникает на живом det; на стенде x40 автовозврат не срывает живой гейт |
| T4 | Quiet 5 мс и dwell 400 мкс в сэмплах tamer (`legion_cmds.c` 550–556) | Считать от readback fs (R3) | Модель: 400 мкс @ фактический fs → hop; @ чужой fs — fail |
| T5 | Мёртвый `fpgaHandoff` + `fpgaAutoCycle` возвращает USB в круг (store 1413, 3043–3056) | Старт автоперехвата и любой UI не вызывают handoff; автовозврат хоста не снимает onboard ARM по выдержке (выдержку делает NIOS) | Старт auto → `fpgaAutoCycle===false`; нет DISARM от хоста через 0.4 мс |

Перенос ADI `sync_event` как обязательная замена heartbeat **не подтверждён**.
Подтверждён T3 на x40.

### 2.4 Наблюдение: водопад и «частота»

| # | Факт | Обязанность | Приёмка |

### 2.5 Числовой тракт и готовность источников (FPGA-ревизия целиком)

Замысел ревизии `legion` включает не только перехват: player, NCO,
lb_always, watchdog (`fpga/README.md` 1–4, 141–146).

| # | Факт | Обязанность | Приёмка |
|---|---|---|---|
| F1 | Soapy CF32 = SC16Q11/2048; тап детектора — те же коды (`fpga/README.md` 199–201) | Не менять формат без сверки порога | GHDL детектора уже в этих единицах; стенд: тон известной амплитуды → det_count растёт при пороге из той же шкалы |
| F2 | Player ARM без `capture_done` — нули на DAC (HDL) | ARM player только при capture_done | Уже есть в шлюзе/доке; стенд E3 обязан FAIL без волны, не SKIP |
| F3 | Mux: ARM=0 / wd / не готов → нули **с каденсом** valid (`legion_tx_mux.vhd` 5–7) | Тишина не держит последний сэмпл на DAC | GHDL mux это бьёт; стенд: после DISARM/wd нет несущей (анализатор/второй приёмник) |
| F4 | lb_shift wrap без saturation (`fpga/README.md` 202–204) | Документ + стендовый подбор с 0 | Не обещать линейный gain |

### 2.6 Образ FPGA и стенд — не опция

Репозиторий: «Без зелёного прогона E1–E6 на целевой плате система
стабильной не считается» (`fpga/README.md` 284–285). В дереве **нет**
timing-отчёта (поиск `*.rpt` / STA — пусто). Старый xA4 с отрицательными
запасами к загруженному образу не привязан — для приёмки он = отсутствует.

Текущие E1–E6 **не доказывают замысел**:

| Этап сейчас | Дыра (факт) |
|---|---|
| E1 ping + set reg | Не доказывает ревизию legion vs hosted кроме 0x80; не сверяет bitstream hash |
| E2 NCO + det_count | Нет кабеля → **SKIP**, fails не растёт → ALL PASS (`acceptance_bench.py` 197–200) |
| E3 player | Нужен Soapy; не проверяет отказ без capture_done как блокер готовности системы |
| E4 det_count | «гейт TX — по HDL-симуляции, на стенде вторым приёмником» — скрипт второго приёмника не имеет, смотрит только счётчик |
| E5 wd_fired | Есть латентность; нет доказательства, что SMA замолчал |
| E6 ping после питания | Не сверяет, что в FPGA именно собранный `legionxA4.rbf` с тем STA |

**Обязательная приёмка рабочей системы** (заменяет «ALL PASS» как критерий):

1. **Сборка** Quartus 23.1.1: `build_bladerf.sh -b bladeRF-micro -s A4 -r legion` (и x40 / xA9, если эти платы в эксплуатации).
2. **STA** того же прогона: WNS≥0, TNS≥0, recovery/removal закрыты по tx/rx/nios доменам. Отчёт хранится рядом с RBF. Образ с отрицательным slack не шьётся.
3. **Идентичность:** hash RBF = hash прошитого (autoload/RAM) = hash в отчёте.
4. **RF-петля обязательна** (TX→RX + аттенюатор или второй приёмник). SKIP кабеля = FAIL системы, не ALL PASS.
5. **Перехват n>1, TURN 400 мкс:** энергия во взгляде 1 → TX есть; через 400 мкс ± допуск PLL/гейт LO на взгляде 2 (частотомер / второй SDR / readback AIR_FREQ + спектр). Допуск hop — время PLL AD9361/LMS, его измерить, не выдумать.
6. **Перехват n=1:** LO не шагает; TX следует за энергией; Стоп и wd гасят SMA.
7. **PRIORITY:** при живой энергии hop нет; после тишины ≥5 мс — hop.
8. **Отказной ARM / частичный AIR / отказ DISARM:** на железе или на NIOS с отказывающим RFIC — тракт не остаётся в TX unmute. На стенде — анализатор не видит несущую после отказного Старта.
9. **0.2 МГц и 2 МГц на micro:** get/readback fs и FILTER 4x; спектр RX показывает полосу взгляда, не «широкий default».
10. **x40 look ≥ 1.5 МГц:** park+hop LMS; look 0.2 — отказ.
11. **Watchdog:** kick пропал → SMA тишина за измеренный интервал (~1 с).
12. **Нагрузка 50 Ом:** мощность на нагрузке записана. Без цифры PA система не «принята».
13. **Soak** 8 ч lb_gated в 50 Ом (`soak_bench.py`) после зелёных пунктов 1–12.

Пока пункт 4 даёт SKIP, система не принята — даже если раннер напечатал ALL PASS.

### 2.7 Тракт ESP32 (если заявлена вся LEGION)

Это второй, независимый продукт в одном репозитории. Замысел: USB → ESP32 →
ADF4351, без SDR (`architecture.md` 71–76). Host-тесты регистров и парсера
есть (`README.md` 128–136). Полноценность этого тракта — свои критерии:
LOCK на заданной частоте, коридор, allowlist, RF OFF после reboot
(compliance). Смешение с FPGA-перехватом запрещено. Нельзя закрыть ESP32
тестами и считать закрытым перехват — и наоборот.

## 4. Что именно сломано относительно замысла (сводка без дыр)

Замысел onboard: ноутбук задаёт коридор, взгляд, порог, выдержку, Старт;
плата сама смотрит аналоговое окно и сама открывает TX; USB только kick и
телеметрия; Стоп и watchdog гасят.

На `c213041` этот замысел **не выполнен** по причинам, которые уже в коде:

1. Отказной Старт может оставить эфир поднятым (U1–U2).
2. Стоп/DISARM может соврать, что погасил (U3).
3. Сбой hop может снять mute на разных LO (U4).
4. Выдержка и коридор нельзя прочитать с платы (U5); «0,4» не 400 мкс (U6–U7).
5. Канал 0.2 и 2 МГц пишутся без FIR 4x и без readback факта (R1–R3) — взгляд на чипе не доказан.
6. Приёмка умеет ALL PASS без RF (E2 SKIP) и без образа с запасом по timing.
7. Водопад не врёт числами спектра, но без подписи оператор читает его как спектр (V1).
8. Мёртвый USB-handoff всё ещё может вернуть хост в круг (T5).

Пункты «частота внутри окна» и «n=1 ARM жив через секунду» **не входят**
в этот список дефектов: они соответствуют написанному замыслу.

## 5. Порядок работ — одна поставка, не «фаза 1 и остальное потом»

Это порядок сборки **одной** рабочей системы. Каждый шаг имеет критерий
из §2. Следующий не начинается с зелёным ALL PASS на заглушках.

1. Зафиксировать §1 в критериях тестов (n=1, взгляд=частота, USB вне круга, handoff мёртв).
2. Сломать набор: отказывающий RFIC, протокол readback, запрет SKIP=PASS. На `c213041` он обязан стать красным (U1–U7, R2).
3. Исправить шлюз и NIOS: валидация → эфир; откаты; честный DISARM; hop mute; readback SCAN/AIR/FILTER/fs; dwell/запятая; FIR 4x; WD от фактического fs; закрыть `fpgaHandoff`.
4. Пока 2–3 красные на старом и зелёные на новом — **не** считать готовым.
5. Собрать xA4 (и x40/xA9 по факту плат) с STA≥0, сохранить отчёт+hash.
6. Прошить **этот** образ, выполнить §2.6 целиком. Нет кабеля / нет анализатора / SKIP — система не принята.
7. Soak 8 ч в 50 Ом. Цифра мощности на нагрузке — в отчёте.
8. ESP32-тракт принимать отдельно, не смешивая со Стартами FPGA.

Пункт 6 не «потом»: без него пункты 3–5 — исправленные исходники, не
рабочая система. Пункт 3 не «вместо» пункта 6: шить текущий снимок
бессмысленно — U/R ещё в коде.

## 6. Что нельзя обещать даже после полного перечня

Это тоже закрытие, не хвост.

- Герц тона внутри взгляда уже окна — другой замысел (§1).
- Модель усилителя и «безопасная» мощность из лимита 1 Вт входа — в коде
  нет. Есть только измерение на 50 Ом (§2.6.12).
- Самовозбуд с антенной на TX при lb_gated — физика, написанная в
  `fpga/README.md` 205–206. Система по замыслу — нагрузка 50 Ом.
- Утечка своего TX в RX держит гейт (`architecture.md` 129–131,
  `fpgaFastpath.ts` 40–43). СТОП и watchdog обязательны всегда; изоляция
  антенн — стенд, не патч детектора.

## 7. Ответ на вопрос «полноценная система по замыслу»

Полноценная система по замыслу — это onboard-перехват, в котором:

- отказ управления не оставляет RF;
- взгляд на AD9361 = запрошенные BW/fs с FIR 4x там, где Nuand требует 4x, и это **прочитано с чипа**;
- выдержка 0.4 мс на нескольких стоянках шагает LO и это **измерено**;
- в одном взгляде TX следует за энергией, пока оператор не Стоп;
- «частота» на экране = центр стоянки, водопад подписан как взгляд;
- образ с неотрицательным timing прошит и сверен;
- SMA в 50 Ом ведёт себя как в §2.6;
- USB-handoff не возвращается;
- ESP32 не участвует.

Сейчас этого нет. Рекомендации U/R/T/V/F и §2.6 — полный закрытый список.
Откладывать стенд, FIR на 2 МГц, readback, честный DISARM или timing
нельзя: любой пропуск оставляет систему не соответствующей замыслу.
