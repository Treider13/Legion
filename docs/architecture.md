┌─────────────────────────────── ПК ───────────────────────────────┐
│  LEGION Control — Tauri v2 desktop (React 19 + TS):              │
│  транспорты: TauriSerial (USB, Rust serialport) · WebSocket      │

## Ключевые инженерные решения (с обоснованиями)

1. **Порядок записи регистров R5→R0, R0 последним** — double-buffered поля применяются только записью R0 (даташит ADI, EngineerZone).
2. **Bit-bang на SFR** (`GPIO.out_w1ts/w1tc`, ~10 МГц) вместо `digitalWrite` (~1–2 мкс) — esp32.com, maarten-pennings. Полная перезапись 6 регистров ≈ 20–40 мкс.
3. **MTLD=1 в режиме коридора** — гашение выхода до захвата петли, чистый свип без выбросов (даташит, EngineerZone).
4. **Fast band select (R3.DB23=1)** — 20 мкс вместо 80 мкс (даташит).
5. **Единая очередь в synthTask** — нет гонок ручной режим ↔ коридор.
6. **NVS-автономность** — после reboot устройство восстанавливает режим (паттерн joseluu/ADF_4351_BT_Smartphone).
7. **SELFTEST** — диагностика SPI без приборов: powerdown→Δтока, polarity→Δчастоты, MUXOUT→мультиметр (методика EngineerZone).
8. **Эталонные тест-вектора** из ADI Eval Software / pyadf435x — защита от ошибок самописного расчёта (инцидент KD0CQ с 2.175 ГГц).

## Производительность (факты)

- Перестройка частоты: band select 20 мкс + settling петли ~100–300 мкс (фильтр типовых модулей 30–35 кГц) → **0.15–0.5 мс**; dwell по умолчанию 10 мс (практика joseluu: стабильно).
- Коридор 2400–2500 МГц — в зоне пика выходной мощности модуля (+4 дБм, измерения dd1us).
- 2475 МГц @ 25 МГц опорник: INT=99, FRAC=0 — чистый integer-N.

## Upgrade path

TI LMX2594/2595 (калибровка <20 мкс, аппаратная рампа) — миграция без смены архитектуры, если ADF4351 перестанет хватать.

## Дополнительные подсистемы (фазы 4–9)

- **WiFi AP/STA + WebSocket :81 + HTTP :80** (lite-UI из LittleFS, gzip). Клиентский пул — 4 слота. (фаза 4)
- **NVS-автономность**: freq/power/ppm/коридор/WiFi восстанавливаются после reboot (паттерн joseluu). RF ON не восстанавливается (compliance). (фаза 4)
- **BLE NUS** (Nordic UART Service, NimBLE 2.5.1): тот же протокол, notify-телеметрия; нет на S2. (фаза 7)
- **PE43702**: аттенюатор 0–31.75 дБ шаг 0.25 дБ, 3 GPIO, MSB-first latch. (фаза 8)
- **Таблица разделов** `partitions_legion.csv`: app 1.6 МБ ×2 (OTA) + LittleFS 512 КБ — default.csv не вмещал WiFi+BLE стек на C3/C6 (проверено сборкой). (фаза 7)
- **OTA**: HTTPUpdateServer, `POST /update` (curl -F image=@firmware.bin). (фаза 9)
- **Релизы**: GitHub Actions → tauri-action, бандлы win/mac/linux по тегу `v*`. (фаза 9)
- **Выравнивание уровня**: разомкнутая калибровка «частота→измеренный dBm» +
  плоский целевой уровень через PE43702 (`SET LEVEL`/`CAL LEVEL`/`LEVEL?`),
  NVS-персистентность; `SET ATT` — ручной override. Компенсирует ~9 дБ разброс
  дешёвого модуля (dd1us). Данные калибровки измеряются прибором; модель
  разомкнутая (для замкнутой АРУ нужен детектор — см. analysis-upgrade.md). (фаза 10)
- **Fast-scan**: delta-запись только изменившихся регистров ADF4351 (R0
  последним) относительно единого кэша реального состояния чипа в `synth`;
  срезает время SPI-записи, физику ФАПЧ не обходит. (фаза 10)
- **Два режима (не смешивать):**
  1. **SDR:** ПК --Ethernet--> SDR; антенна на RX, усилитель на RF out.
     Старт/стоп и события эфира по Ethernet. ESP32 не вызывается.
  2. **ESP32:** ПК --USB--> ESP32 --SPI--> ADF4351 --> усилитель.
     Коридор/скорость. Нет SDR и нет антенны скана.
  Одновременно коридор и SDR TX запрещены (`modeConflict`).
  I/Q на ESP32 не идёт. LAN xA4 = шлюз USB3 + SoapyRemote (RJ45 не в bladeRF).
  N210: RJ45 в сам USRP. Образы: `app/src/sdr/official.ts`.
  Живой скан/TX: Tauri → `tools/sdr_worker.py` → SoapySDR
  (wiki pothosware: Device + CF32 streams). Без Soapy — честный отказ
  или явная эмуляция.
  **Не RF-Clown / не ESP32-BlueJammer:** те проекты — ESP32 + nRF24L01, шум
  по каналам BT/BLE/WiFi 2.4 ГГц, часто закрытый `.bin`, старт при подаче
  питания. Это третий тракт. В LEGION их прошивки и таблицы каналов
  не принимаются (`rejectAlienFirmware`). Режим 2 — ADF4351 по USB,
  не nRF24. Режим 1 — hosted FPGA SDR, не jam-FPGA.
- **Быстрый путь detect→TX (только режим SDR)**: детект и TX LO живут в
  процессе SDR, не в React и не на ESP32. Hop = аналоговая BW устройства
  (bladeRF ≤56 МГц, Nuand), а не узкое окно из UI — идея ice9/blue-dragon
  (стоять в окне, пока полоса влезает). ПЕРЕДАТЬ: улов → TX LO SDR →
  RF out → усилитель. Команды `CUE` / `PA SET I` / `RF ON` на ESP32
  **не отправляются**. Полосы скана (`sdrBands`) и полосы ESP32
  (`allowBands`) — разные списки.
  **Честный бюджет:** host USB3/Soapy retune — сотни µs…мс. Микросекунды
  detect→TX только на FPGA HDL (xA9; xA4 49 kLE тесен). Не реализовано
  и не рисуем. `CUE` остаётся командой режима ESP32 (`synth_apply_fast`).
