# Умная атака — план v3 (на утверждение)

База: `origin/main` после PR #85 (aim / PROTO / 8-slot карта) и #86 (CH_PWR / Top-N / MA-16 = 16 бинов).
Это не код. Это спецификация, которую можно утвердить или вернуть по строкам.

Замысел одной фразой: **после Старта FPGA стоит на плитке и целится в живой канал сетки цифровым окном. Аналоговый LO хопы не догоняет.**

---

## 0. Прицел — что это значит на железе

Не «xlat вырезает канал». Не «walk лочит PRI». Не «max mag на плитке».

| Слой | Что делает | Что не делает |
|---|---|---|
| Хост до ARM | Слушает коридор, строит **список** гипотез, оператор выбирает сетку | Не крутит TX и не остаётся в круге «увидел → усилитель» |
| Аналоговый LO | Стоит на плитке, которую выбрал occupancy | Не прыгает за каждым хопом ELRS (settle 6 мс — политика хоста, не пол AD9361) |
| Occupancy | Счёт/сумма энергии по сетке (`CH_ENERGY` 8×10 МГц уже есть; `CH_PWR` 80×1 МГц уже есть) | Не один глобальный FFT-пик |
| xlat + `legion_lb_aim` | **Извлекает** полосу ~`fs/16` вокруг `CH_TARGET` и ставит её на тот же бин | Не вычитает цель из TX; не «один канал 1 МГц» |
| DRFM 2-tap 0+64 | Два отвода, разнос 64 сэмпла | Walk / `PROTO_PERIOD` против FHSS не включает |
| Walk | Остаётся как лабораторные часы (`period=0` или `4096`, `STEP_SRC=0`) | Не фаза v1. Не RGPO на ELRS |

Целевой ARM умной атаки:

1. LUT/сетка уже на плате (с карточки оператора, не «угадали по пику»).
2. Глухой обзор: score плитки = occupancy сетки, не `max(peak.mag)`.
3. Stare на победившей плитке: `aim_en=1`, `CH_TARGET` из карты с порогом, не live-peak.
4. TX FIFO получает **удержанную** полосу вокруг цели (главный лепесток MA-16), не пустоту и не весь эфир.

## 1. Вердикт по 13 замечаниям

Каждое замечание сверено с кодом на текущем `main` и с физикой. «Принято» = входит в этот план. «Уточнено» = факт верный, вывод предыдущего плана — нет. «Отклонено» = факт в замечании неверен.

### 1.1 Фаза 0 и `max mag` — ПРИНЯТО

Факт. `legion_survey_try_score` берёт `(peak_word >> 8) & 0xffff` и держит максимум за look. `legion_survey_pick` сравнивает `legion_survey_mag[i]`, затем при повторном проходе отдаёт `next_after` (round-robin), а не лучшую плитку.

```2028:2031:fpga/nios/legion_cmds.c
    if (legion_survey_hit[i] == 0 || mag > legion_survey_mag[i]) {
        legion_survey_hit[i] = 1;
        legion_survey_mag[i] = (uint16_t)mag;
```

```1989:1995:fpga/nios/legion_cmds.c
    if (legion_survey_last_i == 0xffffffffu) {
        return best_i;
    }
    if (next_after != 0xffffffffu) {
        return next_after;
    }
```

Look обзора — `LEGION_SCAN_QUIET_MS = 5` мс после settle. Это ~1100 кадров FFT-256 @ 56 MSPS. Копить occupancy за look **уже можно**, HDL-аккумулятор на секунды не нужен.

На `main` уже лежат два счётчика энергии, которые survey **не читает**:

- `CH_ENERGY_0..7` (0x3D–0x44) — 8 слотов × 10 МГц, `g_acc` в `legion_fft_peak.vhd`, абсолютная сетка 2400…2480.
- `CH_PWR` (0x2D) — 80 корзин LUT, сумма `mag_pow` **за один FFT-кадр**, snap 16 бит, `acc` 24 бит сбрасывается на `mag_last`.

План: с Фазы 0 score плитки считается по occupancy, не по пику. Формула — §4.0.

### 1.2 Семантика xlat — УТОЧНЕНО (предположение «режет цель» неверно)

Факт положения в тракте: детектор сидит на сыром RX; в TX FIFO идёт выход xlat (`bladerf-legion.vhd`). Это правда.

Факт операции — не зарубка. `legion_lb_xlat` это xlating FIR:

`(I+jQ)·(cos−j sin) → MA-16 (ФНЧ) → (I'+jQ')·(cos+j sin)`.

MA-16 — усреднение, то есть ФНЧ вокруг DC. После downmix выбранный бин на нуле **остаётся**. После upmix TX получает **полосу вокруг выбранного бина**, а не «всё минус бин».

Следствия:

- Если бин = цель → DRFM **несёт цель** (плюс соседей в главном лепестке). Пустоты нет.
- Если бин = утечка TX, а цель слабее → DRFM несёт утечку, цель в стоп-зоне. Это и есть поломка репитера.
- `LOCK=0` + live `peak_word` выбирает глобальный argmax. Кто громче в плитке — того и извлекаем.
- `aim_en=1` (уже на `main`, PR #85): downmix стоит на `CH_TARGET[7:0]`, не на live-пике. Комментарий в HDL прямо пишет, зачем: иначе `TX = эмиттер − lock + target`.

```24:26:fpga/hdl/legion_lb_xlat.vhd
        -- aim_en=1: downmix = CH_TARGET[7:0], не защёлка пика. Иначе
        -- произведение на новом bin и вырез на старом дают
        -- TX = эмиттер − lock + target.
```

`legion_lb_aim` — второй тракт: база после MA × NCO на тот же `CH_TARGET`. Это и есть цифровой прицел. Не вырезать цель, а **удержать её и поставить на бин**.

План: в умной атаке stare всегда `aim_en` + `CH_TARGET` из occupancy. Live-peak (`LOCK=0` без aim) — лабораторный режим, в ARM умной атаки запрещён. UI не говорит «зарубка цели» и не говорит «зарубка утечки», пока оператор сам не включит отладочный live-peak.

### 1.3 MA-16 ≠ один канал — ПРИНЯТО, но слово «зарубка» неверное

Факт. `LEGION_XLAT_NULL_BINS = 16`. Первый нуль sinc: `f = fs/16`. @ 56 MSPS = **3.5 МГц** = 16 бинов FFT-256. @ 40 MSPS = 2.5 МГц. Шаг ELRS = 1 МГц → в главном лепестке **3–4 канала**.

Это ширина **удержания**, не зарубки. LUT указывает центр окна. Само окно шире канала.

UI: «окно 3.5 МГц вокруг канала N (MA-16)». Не «прицел в канал». Не «зарубка 3.5 МГц». Для FHSS-джамминга широкое окно — плюс: соседние хопы сетки покрыты без скачка LO.

### 1.4 Walk почти ничего не даёт против FHSS — ПРИНЯТО

Факт разноса: `LB_DELAY1_DEFAULT = 64`. @ 56 MSPS это **1.14 мкс**, @ 40 MSPS — 1.60 мкс. Это и есть эффект двухлучевой реплики.

Факт часов. `legion_lb_walk.vhd` сам пишет: «Не PRI-lock и не RFSoC».

- `STEP_SRC=0`, `period=4096`: шаг каждые 4096 сэмплов, пока `det=1`; на тишине счётчик **сбрасывается**. @ 56 MSPS ≈ 73 мкс/шаг. За пакет ~500 мкс — несколько сэмплов. Всё ещё ≪ 64.
- `STEP_SRC=1`, `PROTO_PERIOD = round(PRI·fs)`: счётчик **не** сбрасывается на паузе (уже вшито в #85). Один шаг на PRI. За пакет — доли сэмпла. На 4 порядка меньше разноса отводов.

За один пакет ELRS delay почти константа. Walk не «лочит RGPO» и не синхронизирует реплику с PRI в смысле ISI. ISI даёт **разнос 64**, не его дрейф.

`PROTO_PERIOD` / `DRFM_STEP_SRC` на `main` уже существуют (0x32 / 0x34). Это не повод включать их в умную атаку.

План: фазу walk/FREE **не делать**. HDL не трогать. В ARM умной атаки `DRFM_STEP_SRC=0`. Хост не пишет `PROTO_PERIOD` из матчера.

### 1.5 FREE = стенные часы со случайной фазой — ПРИНЯТО, закрыто п. 1.4

`STEP_SRC=1` уже реализован. Он даёт стену по PRI со случайной фазой относительно пакета. Против FHSS эффект неотличим от лабораторных 4096 (п. 1.4). В v1 не включаем. Формулировка в UI/доке, если кто-то спросит: «PRI-стена — косметика, фаза случайна, для радаров / лаборатории, не для ELRS».

### 1.6 Регистры 0x32–0x34 и JSON — ПРИНЯТО как претензия к старому плану, адреса — ДРУГИЕ

Старый план хотел упаковать 8 полей сетки в 0x32–0x34. На текущем `main` эти адреса **уже заняты** PR #85:

| Адрес | Символ | Смысл |
|---|---|---|
| 0x32 | `PROTO_PERIOD` | период пакета, сэмплы |
| 0x33 | `PROTO_PULSE` | длительность пакета |
| 0x34 | `DRFM_STEP_SRC` | 0=WALK_PERIOD, 1=PROTO_PERIOD |
| 0x35–0x36 | `CH_THR` / `CH_HYST` | порог и гистерезис слота |
| 0x37 | `CH_TARGET` | [7:0] бин, [31] arm произведения |
| 0x38 | `CH_MODE` | 0 = 8×10 МГц ISM, 1 = ELRS 80 |
| 0x39–0x3C | `CH_ACTIVE_*` | битовая карта |
| 0x3D–0x44 | `CH_ENERGY_*` | энергия 8 слотов |
| 0x45–0x4C | `CH_HITS_*` | окна подряд |
| 0x4D–0x4E | `CH_BINS_*` | пик-бин слота |
| 0x4F–0x50 | `CH_FS_HZ` / `CH_LO_KHZ` | сетка для HDL |
| `LEGION_REG_MAX` | `0x50` | дальше — свободно |

`pio_addr` — **7 бит** (`legion_regs.vhd`): доступны 0x00…0x7F. Сетка JSON садится в **0x51…0x57**, не поверх 0x32–0x50. packing — §3.4. Переиспользовать 0x32–0x34 под JSON **нельзя**.

### 1.7 Матчер не видит ZC — ПРИНЯТО

`classify_fhss_domain` смотрит шаг и полосу. Ширина 10/20/40 МГц в хост-атаке помечает «широко / ofdm», не OcuSync. 10 МГц OFDM — это и DJI FPV, и чужие линки, и Wi-Fi-подобное.

ZC уже есть на хосте, не на FPGA:

```44:45:tools/droneid.py
# Только подтверждённые корни (proto17 README, issue #25, RUB-SysSec #46).
ZC_DETECT_ROOTS = ((600, 4), (147, 6))
```

Период вспышки ~600–640 мс (proto17 / NDSS 2023). После ARM IQ на хост не идёт (exclusive USB). ZC — только в слухе до ARM.

План: гипотеза `droneid-zc` только при NCC/ZC hit. Иначе `ofdm-wide` и текст «это не имя OcuSync». Имя модели / 272000 сэмплов — нельзя.

`CH_MODE=0` в заголовке назван `LEGION_CH_MODE_OCUSYNC`, а комментарий `legion_pkg.vhd` честно говорит: 8 слотов = геометрия ISM 80 МГц, **не таблица DJI**. В UI/JSON это `ism8`, не `ocusync`.

### 1.8 «xA4 не видит 5.8» — ОТКЛОНЕНО как факт железа

Замечание повторяет ошибку предыдущего плана. Каталог:

| Железо | RX / TX | 5.8 ГГц |
|---|---|---|
| bladeRF 2.0 micro xA4/xA9 (AD9361) | 70–6000 / 47–6000 МГц | **доступен** |
| bladeRF 1 x40 (LMS6002D) | 300–3800 | **недоступен** |
| ESP32 + ADF4351 (комплект `docs/hardware.md`) | 35–4400 | **недоступен** (потолок 4.4) |

NIOS уже содержит пресет O4: 5768.5 / 5789.5 / 5814.5 МГц (`LEGION_CH_PRESET_O4VID3`). Комментарий AIR: «LO парковки, кГц (47М..6Г)». Тест шлюза принимает коридор 5000–5800 на micro.

Что **невозможно** одной установкой, и это надо писать явно:

- 5.8 на **x40** и на **ADF4351** — потолок железа, не «отложили».
- Две полосы 2.4 и 5.8 одним LO — нельзя (плитка ≤ 56 МГц analog).
- Имя «OcuSync / O4 борт 272000» по ширине — нельзя (п. 1.7).

На xA4 5.8 — штатная полоса каталога. В §6 это ограничение **платформы**, не «v2 когда-нибудь на той же плате».

### 1.9 Смешанный эфир — ПРИНЯТО

`match_spacing` уже возвращает **список** доменов. `classify_fhss_domain` схлопывает его в одну карточку (`unique` или `fhss-overlap`). Аналог / OFDM / ZC идут другими путями и в одну карточку не попадают.

План: матчер возвращает `hypotheses[]` (FHSS-семейства + analog + ofdm-wide + droneid-zc), каждая со своим `conf`. UI показывает все. Оператор выбирает, **какая сетка** уходит в ARM. Остальные висят как «тоже в эфире», без LUT. Если оператор не выбрал — ARM сетки нет, occupancy по пресету не строится, Фаза 3 не притворяется умной.

`unknown` без выбора ≠ тихий ARM с пустым LUT. Это стоп с текстом «сетка не собрана».

### 1.10 Бюджет BRAM — УТОЧНЕНО (считать надо, «120 M10K» — путаница единиц)

Факт устройства: xA4 = `5CEBA4F23C8` (Nuand `platform.conf`: `5CEB${A4}F23C8`). Cyclone V E A4: **308 блоков M10K = 3080 kbit**.

Что уже сидит в BRAM (комментарии репозитория):

| Блок | Объём | Оценка |
|---|---|---|
| `legion_delayline` ×2 | 4096×32 каждый | «16 M9K/M10K» ×2 = 32 |
| `legion_player` | 4096×32 | 16 |
| FFT-256 `ram` + `mag_ram` | 256×32 + 256×16 | ~2 |
| CDC FIFO | 64×32 | <1 |
| xlat MA-16 | 16×I/Q регистры | 0 BRAM |
| `CH_PWR` acc 80×24 + snap 80×16 | регистры | 0 BRAM |
| `CH_ENERGY` 8×32 в peak | регистры | 0 BRAM |

80×24 бит = **1920 бит** = 0.19 kbit. «120 M10K ячеек по 16 бит» — это 120 *слов*, не 120 *блоков*. 1920 / 3_080_000 ≈ **0.06 %**. В fitter это не упирается.

Настоящий потолок 24-битного `acc` в `legion_fft_channelize` — **время до насыщения**, не BRAM. `mag_pow` 16 бит, несколько бинов на канал, кадр 4.57 мкс @ 56 MSPS → насыщение **миллисекунды**, не секунды. Для look 5 мс и stare секунд копить надо в NIOS (`uint32`/`uint64`[80] или [8]) или считать **число кадров выше порога**. Новый M10K-массив не предлагается.

Перед Фазой 3, которая трогает HDL, — прогон fitter и запись ALM/M10K в PR. Для Фазы 0 (только NIOS читает уже существующие mux) fitter не нужен.

### 1.11 Кросс-плиточный f0 — ПРИНЯТО

Один взгляд xA4 ≤ 56 МГц analog, сетка ELRS 79 МГц. `planCenters` даёт **две** плитки. `windowLimited=true`, если span ≥ 0.82·IBW (`fhss_detect.py`).

Якорь 2400.4 работает только если гипотеза уже «ELRS-подобное». Сдвиг, не кратный шагу, даёт f0 **модуло шаг**. Кастом 2000–2100 без якоря из одной плитки не восстанавливается.

План: `f0` из одной плитки = гипотеза, флаг `f0_unconfirmed`. Подтверждение — второй визит соседней плитки **или** оператор жмёт номинал. Без этого LUT на абсолютный f0 не пишется, только относительный step.

### 1.12 Gate `LUT≠0xFF` слишком слабый — ПРИНЯТО

`LUT=0xFF` значит «бин не из сетки». Тихий канал сетки проходит. На `main` stare уже ближе к правильному: `legion_ch_pick` требует `CH_ENERGY[i] ≥ CH_THR` и `CH_HITS[i] ≥ CH_HYST`. Для ELRS дополнительно `legion_ch_elrs_of_khz != 0xFF`.

Дырка: ELRS-маска красится **всем 10-МГц слотом** (`legion_ch_elrs_mark_slot`) — 10 каналов с одного слота. Это не «канал активен», это «слот активен».

План: менять `CH_TARGET` только если слот/канал **активен по энергии** (`CH_ENERGY≥THR` или `CH_PWR(ch)≥THR`) **и** LUT валиден. Не «бин попал в сетку». Фаза 3 добавляет чтение `CH_PWR` внутри stare для 1-МГц сетки; 10-МГц слот остаётся грубым fallback.

### 1.13 `FreqCorrection ±200 кГц` — ПРИНЯТО

В репозитории строки `FreqCorrection` нет. Upstream ExpressLRS `FHSS.h`:

- SX128x (ISM 2.4): `FreqCorrectionMax = 200000 / FREQ_STEP` → **±200 кГц**
- SX127x / LR1121: **±100 кГц**

Допуск матчера «½ шага» при шаге 1 МГц = 500 кГц. Штатная коррекция внутри допуска. STFT/FFT-256 не отличит её от кастомного сдвига 200 кГц.

План: не сужать допуск ниже разрешения. В карточке: `|shift| ≤ 200 кГц` на 2.4 → «штатная FreqCorrection, не кастом». `|shift| ≤ 100 кГц` на 900. Больше — «сдвиг прошивки / не якорь».

## 3. Спецификации (не наброски)

### 3.1 xlat — однозначная семантика

Имя в UI и доке: **окно извлечения**, не зарубка.

| Режим | Условие | Downmix | TX FIFO | Когда |
|---|---|---|---|---|
| `AIM` | умная атака, stare | `CH_TARGET[7:0]` | полоса ~fs/16 вокруг цели | **дефолт Smart Attack** |
| `BYPASS` | Gemini / два тона ≥ 16 бинов / оператор «вся плитка» | нет (in→out) | весь взгляд | уже авто на два тона; вручную — широкий джем |
| `LIVE` | `aim_en=0`, `LOCK=0` | live `peak_word` | полоса вокруг глобального пика | **лаборатория, в Smart Attack ARM запрещён** |
| `LOCK` | выдержка без aim | защёлкнутый бин | полоса вокруг защёлки | обычный приоритет/TURN, не ИИ |

Запрещённая комбинация умной атаки: `LOCK=0` + live-peak + цель слабее утечки. Она извлекает утечку.

`CH_TARGET[31]=1` вооружает произведение `legion_lb_aim`. Снимать arm, не сняв политику, нельзя: HDL специально держит downmix на том же бине, пока aim жив.

### 3.2 Ширина окна в UI

```
null_hz = fs / 16
null_bins = 16
```

Строка оператору: `окно {null_hz/1e6:.1f} МГц · центр канал {n} · {f0+n·step} МГц`.
Не «канал», не «зарубка», не «прицел 1 МГц».

### 3.3 Walk

В ARM умной атаки:

- `WALK_PERIOD` = 0 (шаг по фронту det) **или** 4096, как сейчас лабораторный дефолт. Не из PRI.
- `DRFM_STEP_SRC` = 0.
- `PROTO_PERIOD` / `PROTO_PULSE` не пишутся из матчера.
- 2-tap 0+64 + амплитуды 0.5+0.5 — без изменений.

### 3.4 Регистры сетки 0x51–0x57

Не занимать 0x32–0x50. `LEGION_REG_MAX` сдвинуть на `0x57`. Писать и в `legion_pkg.vhd`, и в `legion_cmds.h`, и в `legion_fpga.py` одним PR. Тест: запись/чтение каждого поля + отказ адреса > MAX.

#### 0x51 `GRID_META`

| Биты | Поле | Тип |
|---|---|---|
| 7:0 | `n` | каналов в таблице семьи (1…80) |
| 15:8 | `n_used` | наблюдаемых (mLRS 24/18/12; 0 = неизвестно) |
| 23:16 | `confidence` | 0…255 |
| 27:24 | `source` | 0 none, 1 matcher, 2 preset, 3 operator, 4 second-tile |
| 31:28 | `kind` | 0 unknown, 1 fhss-narrow, 2 ofdm-wide, 3 analog, 4 droneid-zc, 5 cw |

#### 0x52 `GRID_F0_HZ`

Абсолютный f0, Гц, uint32. 0 = сетки нет. ELRS ISM2G4 = 2_400_400_000.

#### 0x53 `GRID_STEP_HZ`

Шаг, Гц, uint32. ELRS = 1_000_000. 0 = сетки нет.

#### 0x54 `GRID_PRI_US`

Оценка периода, мкс, uint32. 0 = нет / не использовать как часы walk.

#### 0x55 `GRID_SHIFT_HZ`

Signed int32. Residual относительно номинала семьи. Для UI FreqCorrection.

#### 0x56 `GRID_FLAGS`

| Биты | Флаг |
|---|---|
| 0 | `window_limited` |
| 1 | `f0_unconfirmed` (одна плитка) |
| 2 | `zc_hit` |
| 3 | `freqcorr_in_band` (\|shift\| ≤ лимита семьи) |
| 7:4 | `hyp_index` выбранной гипотезы |
| 15:8 | `hyp_count` |
| 23:16 | `window_bins` (писать 16, не «1 канал») |
| 31:24 | reserved 0 |

#### 0x57 `GRID_N_USED_MASK` (опционально v1.1)

Нижние 32 бита used-маски. Для v1 достаточно `n_used` в META.

JSON хоста (зеркало, не «как-нибудь»):

```json
{
  "n": 80,
  "step_hz": 1000000,
  "f0_hz": 2400400000,
  "pri_us": 2000,
  "n_used": 80,
  "confidence": 180,
  "source": "matcher",
  "kind": "fhss-narrow",
  "shift_hz": -80000,
  "window_limited": true,
  "f0_unconfirmed": true,
  "zc_hit": false,
  "freqcorr_in_band": true,
  "hyp_index": 0,
  "hyp_count": 3,
  "window_hz": 3500000,
  "window_bins": 16
}
```

NIOS при ненулевых `f0`+`step`+`n` перестраивает LUT формулой `ch = round((f_bin − f0) / step)`, `0xFF` если \|residual\| > step/2 или ch вне [0, n). Это уже делает `legion_ch_map_bin` для пресета ELRS; параметрический путь — те же строки с регистрами вместо констант 2400.4 / 1e6 / 80.

### 3.5 Мульти-гипотезы

Выход матчера — массив, не одна карточка.

```
Hypothesis {
  id, family, kind, label,
  n, step_hz, f0_hz, pri_us, n_used,
  shift_hz, conf,          // 0..1 → confidence 0..255
  zc_hit, window_limited, f0_unconfirmed,
  freqcorr_in_band,
  source,                  // "spacing" | "zc" | "analog-comb" | "operator"
  note                     // человеческая строка
}
```

Правила:

- ELRS и mLRS на шаге 1 МГц — **две** гипотезы, не одна `fhss-overlap`. `n_used` 80 vs {24,18,12} различает, если hop-set это показал; иначе обе с пометкой «шаг общий, выбери».
- Analog PAL + FHSS в одном коридоре — две kind.
- 10 МГц OFDM без ZC — `ofdm-wide`, не OcuSync.
- ZC 600/147 — отдельная `droneid-zc`.
- Оператор может править f0/step вручную → `source=operator`.

### 3.6 Железо 5.8 — явная таблица

В UI Старта: платформа из каталога. Если выбран x40 или тракт ADF4351 — полоса ≥ 4.4 / 3.8 ГГц **не предлагается**, текст: «эта плата сюда не достаёт». Если xA4/xA9 — 5.8 доступен, но метка остаётся `ofdm-wide` / `analog` / `droneid-zc`, не «O4 борт».

### 3.7 HDL-бюджет (до любой правки VHDL)

Фаза 0 и Фаза L — только NIOS/хост. Новых массивов в M10K нет.

Если позже кто-то предложит HDL-аккумулятор на секунды: не расширять 24-бит `acc` (насыщение за мс). Либо NIOS, либо счётчик кадров 16–24 бит на канал (80×24 FFs, не BRAM). Потолок каналов 80 не поднимать.

Перед PR, который трогает `legion_fft_*` / delayline / xlat: вложить строку Quartus (ALM, M10K, Fmax) относительно текущего `main`.

## 4. Фазы

Фазы 4 (walk FREE) **нет**.

### Фаза L — слух до ARM (хост)

Зачем: после ARM IQ на ноутбук не идет. Сетку и ZC надо снять здесь.

Сделать:

1. По Старт умной атаки не звать сразу `startOnboardIntercept`.
2. Коридор пройти хост-слухом (Thomson DPSS×3, как атака). Плитки те же `planCenters`.
3. Собрать признаки: step, unique, residual f0, n_used, pri, ширина, analog-гребёнка, ZC 600/147.
4. Показать **все** гипотезы. Оператор выбирает одну (или правит f0/step).
5. Если `window_limited` — текст: «f0 с одной плитки — гипотеза». Кнопка «дойти вторую плитку» или «принять номинал 2400.4».
6. `|shift|≤лимита` → «FreqCorrection, не кастом».
7. Подтверждение пишет JSON §3.4 и только тогда ARM.

Не делать: авто-ARM по первой гипотезе; имя OcuSync без ZC; запись `PROTO_PERIOD=272000`.

Приёмка:

- Фикстура ELRS 80×1 → карточка elrs + карточка mlrs (шаг общий).
- Фикстура 10 МГц OFDM без ZC → `ofdm-wide`, не OcuSync.
- Фикстура proto17 ZC → `droneid-zc`.
- Фикстура ELRS + PAL → две kind.
- x40 + коридор 5.8 → отказ, не ARM.

### Фаза 0 — score плитки = occupancy

Зачем: иначе ИИ после confirm снова встанет на плитку с одним громким CW.

Сделать в NIOS, без нового HDL:

Во время PASS, после first-valid FFT, пока `now − quiet_t0 < 5 мс`:

```
score_count = 0
score_sum   = 0
каждый новый кадр:
    прочитать CH_ENERGY_0..7          // 8 mux, уже есть legion_ch_read_map
    для слотов, пересекающих look:
        если GRID есть и слот вне сетки — пропуск
        score_sum += energy[s]
        если energy[s] ≥ CH_THR (или >0, если THR=0):
            score_count++
записать look: (count, sum)
pick = argmax count, ничья → большая sum, ничья → меньший индекс
next_after УБРАТЬ из pick умной атаки
```

Если сетка 80×1 уже в LUT: дополнительно (не вместо) можно раз в look пройти `CH_PWR[0..79]` и считать каналы ≥ порога. 80 PIO за кадр ≈ десятки микросекунд — в 5 мс влезает много снимков. Первый PR имеет право ограничиться восьмёркой `CH_ENERGY`: она уже в mux и бьёт max-mag.

`CH_THR=0` после ARM без карточки: count вырождается, остаётся sum. Это честный fallback, не «как будто сетка есть».

Приёмка:

- Плитка A: один CW 0 дБ. Плитка B: три слота сетки −12 дБ. Pick = B.
- Повторный PASS не уходит на next_after, если B всё ещё лучше.
- Look без det и с нулевой картой → pick пустой, новый PASS, не stare на мусоре.

### Фаза 1 — UI коридора и карточки

- Старт умной атаки = Фаза L → карточки → ARM.
- На карточке: kind, f0, step, n/n_used, shift + пояснение FreqCorrection, окно МГц (не «канал»), `window_limited`, список соседей по эфиру.
- Ручной f0/step.
- После ARM ноутбук — рубильник. Хозяин — SDR.

Приёмка: e2e без платы — фейковый слух → карточка → JSON регистров 0x51–0x56 → `op:arm` с теми же полями. Отмена карточки → ARM нет.

### Фаза 2 — регистры 0x51–0x57 и параметрический LUT

- Карта §3.4 в VHDL / NIOS / Python / тестах.
- `legion_ch_rebuild_lut` для `source≠preset`: f0/step/n из регистров.
- Пресеты ELRS / ISM8 / O4VID3 остаются ярлыками. ISM8 в UI не зовётся OcuSync.
- Хост после confirm пишет 0x51–0x56 одним блоком до `CTRL.ARM`.

Приёмка: запись 0x32 не меняет сетку; запись 0x52/0x53 меняет LUT; адрес 0x58+ → `bad addr`, пока не специфицирован.

### Фаза 3 — stare прицельный

Уже почти собрано (`legion_channel_scan`, `legion_aim_set`). Доделать:

1. После confirm LUT живой. `aim_en` обязателен в stare умной атаки.
2. Gate смены `CH_TARGET`: `det ∧ energy≥THR ∧ hits≥HYST ∧ (LUT(ch)≠0xFF) ∧ (для 80-сетки: CH_PWR(ch)≥THR)`.
3. Не красить 10 ELRS-каналов с одного 10-МГц слота как «все активны». Маска ACTIVE_1..3 — индикация, не разрешение aim. Aim — бин слота / канал с `CH_PWR`.
4. Gemini / два тона ≥ 16 бинов: как сейчас, bypass и aim не вооружать.
5. Resurvey по `SCAN_SURVEY_US` остаётся. Score снова occupancy (Фаза 0), не peak.

Приёмка:

- Сильный CW вне сетки, слабый хоп в сетке → `CH_TARGET` на хоп, не на CW.
- Тихий канал LUT без энергии → aim туда не уезжает.
- Смена канала внутри плитки не делает analog hop и не сбрасывает DRFM (уже заявлено в комментарии NIOS — закрепить тестом).

## 6. Порядок и зависимости

```
L (хост слух + карточки + ZC)
  └─ 0 (NIOS: pick по CH_ENERGY; убрать next_after)
       └─ 1 (UI confirm → ARM)
            └─ 2 (0x51–0x57 + LUT из f0/step)
                 └─ 3 (gate CH_PWR + aim-only stare)
```

0 можно делать параллельно с L (разные деревья). 3 без 0 бессмысленна: stare будет на чужой плитке. 2 без L оставит пресеты-якоря (ELRS 2400.4) — допустимый лабораторный путь, не полевой.

## 7. Приёмка продукта (умная атака прицельная)

Сценарий ELRS 2.4, xA4, коридор 2400–2480:

1. Старт → слух двух плиток → карточки ELRS и mLRS → оператор берёт ELRS (или номинал, если `f0_unconfirmed`).
2. JSON: step 1e6, f0 2400.4e6, window 3.5 МГц, `freqcorr_in_band` если \|shift\|≤200 кГц.
3. ARM: survey pick по числу живых слотов, не по CW на соседней плитке.
4. Stare: LO стоит. `CH_TARGET` скачет по активному каналу/слоту. Analog hop нет.
5. Спектр TX: энергия в окне ~3.5 МГц вокруг живого канала, не дырка на цели и не весь 56 МГц.
6. Walk не следует за PRI. Отводы 0+64 на месте.

Если пункт 3 или 5 не выполняется — это не умная атака, это старый survey + xlating на пик.
