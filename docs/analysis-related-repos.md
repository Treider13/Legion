# LEGION — разбор шести открытых проектов (по коду, не по README)

Документ фиксирует **факт из репозиториев** на дату разбора (2026-08-31).
Звёзды/форки — живые числа GitHub, не устаревшие упоминания. Ни один из
шести проектов **не копируется в код LEGION**: это аналитика смежных идей
(приоритизация целей, DSP-массив, теория игр частотного хоппинга,
планирование покрытия, RSS-геолокация). Правовая рамка та же, что в
[compliance.md](compliance.md): лабораторный генератор, нагрузка 50 Ом.

> **Как читать.** У каждого проекта три слоя: (1) что обещает README,
> (2) что реально в исходниках, (3) что из этого вообще относится к
> тракту LEGION (сканер energy-detection → ПРИОРИТЕТ/ОБЫЧНЫЙ → FPGA
> `lb_gated` / ADF4351). Код и формулы цитируются по клону; если README
> врёт — это сказано прямо.

## 1. deeprl-counter-uav-swarm (Palmas, 2025)

**Репозиторий:** https://github.com/alexpalms/deeprl-counter-uav-swarm
**Статья:** arXiv:2508.00641, *Reinforcement Learning for Decision-Level
Interception Prioritization in Drone Swarm Defense*.
**Стек:** Python, Gymnasium, Stable-Baselines3 MaskablePPO, `uv`/`pyproject.toml`.
**Лицензия:** MIT.

### Что обещает README

RL-агент учится, какую цель атаковать первой, чтобы минимизировать ущерб
защищаемым зонам. Сравнение с «классической» эвристикой. «Реалистичная»
кинематика оружия, LOS, multi-agent, конфигурируемые сценарии.

### Что в коде

Это **одноагентный MDP назначения целей**, не физический C-UAS и не MARL.

| Элемент MDP | Факт |
|---|---|
| Действие | `MultiDiscrete`: каждый из 4 эффекторов выбирает индекс дрона 0…49 |
| Наблюдение | Dict: шумные XYZ, az/el, FSM оружия/дронов; **истинная** мощность БЧ в obs |
| Награда | Разреженная: \(r = -\sum\) `potential_damage` в тик удара. Нет shaping за трек/выстрел |
| Эпизод | `dt = 0.1` с, пока не кончатся траектории |

Ущерб зоны (при ударе):

\[
\text{potential\_damage} = \max\bigl(1,\ \sum_{z:\ \text{конец}\in z} v_z \cdot 3^{e}\bigr),\quad e\in\{0,1,2\}
\]

Зоны (жёстко в `Environment.__init__`, YAML их **не** задаёт):

| ID | Центр | Радиус | Ценность \(v_z\) |
|---|---|---|---|
| 0 | (−30, −50) | 10 | 2 |
| 1 | (−30, 50) | 30 | 5 |
| 2 | (−60, −10) | 20 | 10 |

Обучение (`examples/config.yaml`): MaskablePPO, **80 млн** шагов, **32**
параллельных env, γ = 0.998, сеть Linear(566→64)+ReLU, CPU. Маска действий
скрывает только мёртвых дронов — не «уже назначен», не «вне зоны».

Базовая эвристика `DistanceBasedAgent` — не «ближайший», а угроза:

\[
d_w = \sum_z \frac{\|p-c_z\|}{v_z r_z},\quad
d_w \leftarrow \frac{d_w}{e_{\text{det}}+1}
\]

затем k наименьших. RL эту фичу **не видит** (wrapper её выкидывает) — сравнение
несимметричное.

**Физика — игрушечная.** Дроны летят открытым waypoint-скриптом (скорости
{10,20,30}). Эффектор — поворот az/el с ограничением скорости + «луч»
бесконечной дальности. Снаряда, TOF, секера, РЭБ нет. PK — кусочно-линейная
таблица; бакеты расстояний в коде **не отсортированы**
(`[0.0, 0.5, 0.25, 0.5]`) — `bisect_left` на неотсортированном входе даёт
сломанную PK. Тесты: 3 смока «агент сделал шаг», без проверки награды/PK.

Таблица README (40.7 % vs 52.1 % ущерба) — артефакт `results/`, не
воспроизводится тестами репозитория.

### Честные ограничения

- Нет радара, EW, кинетики снаряда, местности, ответных манёвров роя.
- Сценарий нельзя сменить конфигом — только правкой Python.
- Не цифровой двойник и не калибровка по лётным данным.

### Что это значит для LEGION

У нас ПРИОРИТЕТ — жадный выбор **сильнейшего живого бина**
(`pickStrongest` в `app/src/sense/orchestrator.ts`, `pickPriorityTarget` в
`hold.ts`): «рядом появилась сильнее — переключаемся». Palmas показывает
другой класс задачи: при **нескольких** целях и **ограниченном** ресурсе
(у нас — один LO / один FPGA-гейт) мгновенный максимум мощности не обязан
быть лучшим решением на горизонте эпизода.

**Брать (идея, не код):** скоринг живых пиков богаче, чем `max(powerDbm)` —
устойчивость (сколько dwell живёт), запас над порогом, не прыгать на
вспышку на 0.2 дБ. Это оркестратор сканера, не «ИИ-ПВО».

**Не брать:** PPO/MaskablePPO, кинетические эффекторы, PK-таблицы,
«нейтрализацию» дронов, любые payload из `model.zip`.

## 2. drone-defense-simulator (theYsnS)

**Репозиторий:** https://github.com/theYsnS/drone-defense-simulator
**Стек:** Python, numpy. Один коммит. 13 файлов, ~7 КБ на GitHub.
**Лицензия:** файл LICENSE есть, SPDX на GitHub — NOASSERTION.

### Что обещает README

Симулятор C-UAS: радиолокатор, ML-классификация (квадрокоптер / самолёт /
гибрид), оценка угрозы, зоны обнаружения/предупреждения/огня, модуль РЭБ
(RF jamming + GPS spoofing), Kalman, PyGame, сценарии YAML, `python main.py`.

### Что в коде

Пять несвязанных классов. **Нет `main.py`.** YAML никто не читает.
`pygame` / `opencv-python` / `pyyaml` в `requirements.txt` — в `src/` не
импортируются. История git: недостающих кусков никогда не было.

**«Радар»** (`src/radar.py`) — геометрические ворота дальность + RCS +
Bernoulli. Угол скана крутится, но **не используется** (все цели в круге
равноправны). «Сила сигнала» \(rcs / (d^4+\varepsilon)\) пишется в контакт
и **не влияет** на обнаружение. Частоты, G, Pt, CFAR, луч — нет.

**«ML-классификация»** — один тернарный оператор в `ThreatAssessor.assess`:

```
Nano UAV        если rcs < 0.02
Small Quadcopter если rcs < 0.06 и speed < 25
Fixed-Wing UAV  если speed > 30
Medium UAV      иначе
```

Нет sklearn/torch, нет обучающей выборки, тип дрона из `DroneType` игнорируется.

**«РЭБ»** (`DefenseController`): CRITICAL → флаг `RF_JAMMER.is_active`;
HIGH → флаг `GPS_SPOOFER`. Дрон **не меняет** траекторию, SNR, навигацию.
`Drone.neutralize()` ниоткуда не вызывается. Кулдаун не тикает — после
первого ENGAGE слот навсегда занят. `NET_CAPTURE` объявлен и не выбирается.

**Kalman** (`KalmanTracker`): учебный 2D CV, состояние `[x,y,vx,vy]`,
измерение только позиции, `Q=0.1 I`, `R=10 I`. Ни один другой модуль его
не вызывает. Нет мультитаргета / ассоциации.

**Угроза.** Счёт (cap 100) — линейная комбинация близости/скорости/схождения/
высоты/RCS. **Уровень** (то, чем стреляет контроллер) считается **не по
счёту**, а по радиусам 500 / 2000 м. Можно иметь высокий score и LOW.

Тесты: `len(contacts) ≥ 0` (всегда истина), `|x| < 1001` после 1 с полёта
с x=1000. ThreatAssessor и DefenseController не покрыты.

### Честные ограничения

Это не симулятор. Это набросок интерфейсов классов плюс рекламный README.
На нём нельзя ни исследовать доктрину C-UAS, ни «классифицировать дроны ML».

### Что это значит для LEGION

Прямого заимствования нет. Единственный здоровый *класс идей* — сопровождение
цели во времени (ассоциация пиков между кадрами скана). У нас уже есть
`mergeDetections` по бину частоты (`orchestrator.ts`, окно 48). Это не Kalman
и не надо им прикидываться.

**Не брать:** флаги jamming/spoofing, «классификацию» по RCS, PyGame-HUD,
YAML-сценарии, любые формулировки «модуль РЭБ» без физики.

## 3. Intelligent-Anti-Jamming (Madhava005)

**Репозиторий:** https://github.com/Madhava005/Intelligent-Anti-Jamming.
(точка в имени репозитория).
**Стек:** numpy, matplotlib. ~900 строк. MIT.

### Что обещает README

Сначала MUSIC оценивает направление помехи, затем RL динамически настраивает
антенну (MVDR), чтобы подавить помеху и сохранить полезный сигнал.

### Что в коде

Три модуля **не соединены** так, как нарисовано.

**Модель сигнала** (`Signal_Model.py`): узкополосная ULA, N=16, \(d=\lambda/2\),
два комплексных тона (0.1 и 0.2 цикла/отсчёт), 1000 снимков. **Нет несущей,
нет fs, нет полосы.** Шум — **одна** комплексная последовательность, скопированная
на все элементы (`outer(ones, noise)`). Ковариация шума ≈ \(\sigma^2\mathbf{1}\mathbf{1}^H\),
не \(\sigma^2 I\). Sample covariance почти вырождена (`cond(R)` огромный).

**MUSIC** (`music.py`): учебный Schmidt — \(R\), шумное подпространство,
\(P(\theta)=1/\|U_n^H a(\theta)\|^2\), сетка 0.5°. Баги: один `argmax` при
двух источниках (не разделяет сигнал и помеху); `true_jammer_angle=30`
зашит навечно, хотя в `main.py` помеха гуляет; `num_sources=2` — оракул.
**Оценка угла никуда дальше не передаётся.**

**MVDR** (`beamforming.py`): \(\mathbf{w}=R^{-1}a/(a^H R^{-1}a)\). Направление
ограничения — **известный** \(\theta_s\), не выход MUSIC. Без diagonal loading,
`inv(R)` на вырожденной \(R\).

**RL** (`rl_agent.py`): табличный Q-learning, 3 состояния SINR (LOW/MED/HIGH),
3 действия {Hold, Recompute MVDR, Adjust ±2° look-direction}. Это **не**
управление весами и **не** null-steering. В отдельном `simulate_beamforming_environment`
награда — гауссианы, прибитые к типу действия (action 1 заранее «лучший»).

**Фальшивый SINR в `main.py` (решающий дефект):**

```
signal_power = mean(|y|²)
interference_power = 0.1 * signal_power
noise_power = 0.01
```

«Помеха» = 10 % полной мощности на выходе. Тогда
\(\mathrm{SINR}\to 10\,\mathrm{dB}\) почти при любых весах, включая случайные.
Награда RL \(=\Delta\mathrm{SINR}\) — шум вокруг константы.

Цикл `main.py`: случайное блуждание \(\theta_j\) → синтез \(X\) → MUSIC
(печать) → Q-действие → опционально MVDR с оракульным \(\theta_s\) → фейковый
SINR → апдейт Q. 60 шагов, `plt.show()`.

### Честные ограничения

- Одна ULA, far-field, два тона, известное число источников, известный \(\theta_s\).
- Нет SDR, калибровки, взаимного влияния элементов, широкой полосы, FH.
- Заявленный конвейер «MUSIC → RL → null» **в коде отсутствует**.

### Что это значит для LEGION

MUSIC и MVDR — настоящие алгоритмы **решётки**. У LEGION один RX-канал SDR
(bladeRF / HackRF / …) и energy detection (Welch). Без калиброванной
антенной решётки (ULA/UCA) эти формулы неприменимы. Табличный Q-learning
здесь не «адаптивная защита», а демо с поддельным фидбеком.

**Не брать:** модули, «RL anti-jam», любые графики `results/` как доказательство.
**Не обещать** в UI «пеленг MUSIC» с одной антенны — это та же ложь, что у них
в README.

Если когда-нибудь появится отдельный массив (не ADF4351, не один SMA) —
это другой прибор и другой документ. Пока железа нет, кода нет.

## 4. Counterfactual-Regret-Minimization-for-Anti-Jamming-Game-of-Frequency-Agile-Radar

**Репозиторий:** https://github.com/lhy6968/Counterfactual-Regret-Minimization-for-Anti-Jamming-Game-of-Frequency-Agile-Radar
**Статья:** Li, Han, Pu, Liu, Li, Jiu. IEEE SAM 2022. DOI 10.1109/SAM53842.2022.9827883.
arXiv:2202.10049.
**Стек:** OpenSpiel + PyTorch, каталог `IEEE SAM coding/`. SPDX лицензии нет
(в файлах — заголовки Apache DeepMind, код сильно переписан).
**Размер:** ~625 МБ, в git залиты `.pkl` чекпоинты и `__pycache__`.

### Что обещает README / статья

Противостояние «частотно-гибкий радар vs постановщик помех» как игра с
неполной информацией. Deep CFR ищет приближённое равновесие Нэша. Радар
выбирает частоты субимпульсов, помеха — спот / barrage / adaptive.

### Что в коде

Это **настоящая** (упрощённая) радиолокационная модель, завернутая в
дискретную игру, и **компрометированная** реализация Deep CFR.

**Игра** (`Environment.py`): 2 игрока, zero-sum, 4 импульса × 3 субимпульса.
Радар: 27 действий = все тройки из {0,1,2}. Помеха: 5 меток (спот на f0/1/2,
adaptive=30, barrage). Терминальный выигрыш радара — вероятность обнаружения
\(P_d\), помехи \(=-P_d\).

**Физика payoff (не ±1-матрица):**

\[
\mathrm{SINR}=\frac{P G^2 \lambda^2 \sigma}{(4\pi)^3 R^4 N},\quad
N=k T_0 B
\]

Спот на той же частоте → субимпульс **выбрасывается** из детектора.
Barrage даёт ослабленный \(\sigma\) (в коде деление на необъяснённые 5000).
Порог из смеси \(\chi^2\) при \(P_f=10^{-4}\), затем \(P_d=1-F(T)\).
Численно в логах `testing_result/`: средний \(P_d\) ≈ 0.80…0.89.

**Сломанный «одновременный ход»:** комментарий говорит, что ходы одновременны
(токен 99 прячет действие радара), но adaptive-действие 30 в `_apply_action`
читает `self.radar_action` — помеха **видит** частоты радара в том же
импульсе. Это не та информационная структура, которую декларирует статья.

**Deep CFR** (`deep_cfr_algorithm.py`): advantage-сеть и strategy-сеть на
игрока, reservoir memory, regret matching. MLP собран как `Sequential` из
одних `Linear` **без нелинейностей** → фактически одно аффинное отображение.
Эмбеддинг доски в `Embedding.py` крутит только `range(2)` из 4 импульсов —
история дальше 2-го импульса сети не видят. Traversal режет ветвление
(`limitation = 2`). Импорты в тест-скриптах часто битые
(`import radar_game` при файле `Environment.py`).

Варианты DQN/NFSP в том же дереве часто **замораживают помеху на действие 30**.
Это не взаимное обучение двух сторон.

### Честные ограничения

- 3 частоты, 4 импульса — игрушечный алфавит относительно реального FA-радара.
- Чекпоинты не портируются в closed-loop контроллер платы.
- Нет Доплера, сопровождения, неопределённости дальности/ЭПР, задержки
  обнаружения спектра помехой.
- Заявленное качество Нэша в репозитории не подтверждено exploitability-логом.

### Что это значит для LEGION

Смежная идея: **предсказуемый** коридор/качание легче «сопровождать», чем
смешанную стратегию по сетке. У нас уже есть HOP с воспроизводимым seed
(`mulberry32` в `scan.ts`, режим СЛУЧАЙНАЯ). Это лабораторный стимул для
проверки приёмника, не «перехитрить постановщика».

Deep CFR / OpenSpiel / `.pkl` — исследовательский дамп. В прошивку, FPGA и
оркестратор не переносится. Не подписывать в UI «CFR-стратегия».

**Брать (идея):** payoff операционной метрики (у нас — захват/удержание пика,
не \(P_d\) радара), а не «красивый спектр». Смешанный хоп как **тест-стимул**.
**Не брать:** сети, 27×5 таблицы действий, действие-30, любые «anti-jam game»
циклы на эфир.

## 5. SpectralEye (njavro)

**Репозиторий:** https://github.com/njavro/SpectralEye
**Стек:** React + Cesium/Resium + Zustand (фронт); FastAPI (бэкенд-прокси);
опционально Google Colab T4 + Sionna RT + cloudflared.
**Лицензия:** нет файла. ★ 0.

### Что обещает README

«Цифровой двойник» для командира РЭБ: 3D-город, расстановка средств,
рой дронов, GPU-расчёт распространения (Sionna), в реальном времени видно,
какие дроны «зажаты», какие прорываются.

### Что в коде

Два разных движка, которые README склеивает в один нарратив.

**Когда Colab-туннель жив:** Sionna `RadioMapSolver` считает **карту принятой
мощности** одного TX (изотроп, V-пол) по OSM-экструзии зданий, по срезам
высоты (типично 25 м воксель, 0–100 м AGL, 4 среза). Это честный (грубый)
ray-trace path gain → dBm. Материалы в Mitsuba — `diffuse` reflectance 0.5
с ярлыком `itu_concrete`, **не** радиоматериалы ITU Sionna. Google 3D Tiles
на глобусе — косметика: солвер их не видит. Высота TX на Colab берётся из
OSM, не из WGS84 пика на глобусе.

**Когда GPU нет:** Friis + 20 дБ «город». `fake_remote_dev.py` всё равно
пишет `"source": "sionna_remote"` — UI может врать про точность.

**«SJR» и «убийство» дрона — эвристика браузера, не ЭМ:**

\[
\mathrm{SJR} = -55\,\mathrm{dBm} - P_{\text{jammer}}(x),\quad
\text{jammed} \iff \mathrm{SJR} < 10\,\mathrm{dB}
\]

Константа −55 дБм — «мощность канала управления везде». Нет GCS, нет
бюджетa линии, нет FHSS/DSSS, нет антенны оператора. Дрон летит 15 м/с
на 50 м AGL (игнорируя здания) и **замирает** на первом кадре ниже порога.
Сэмплер берёт **max по вертикальному столбцу**, не точку на высоте дрона —
намеренно, чтобы «не пролететь под облаком». Порог красной EMS-оболочки
джаммера (−40 дБм) **не равен** порогу contested/kill (−65 дБм) — картинка
и «физика боя» расходятся на 25 дБ.

«Текущая расстановка» — RNG: ровно по одному jammer/sensor/relay со
случайными координатами. Живого C2/MQTT/железа нет. Туннель Colab:
URL меняется каждый сеанс, idle ~90 мин, Overpass 429, lock на GPU.

Качество кода фронта/контракта — выше среднего для прототипа (~5.5k LOC,
чистые `SionnaSource` / `DeploymentSource`). Тестов почти нет. Docs в
дереве пустые, вопреки README.

### Честные ограничения

Это сильный **демо-UX** планирования на Cesium и слабый **EW engagement
model**. Не валидировано полевыми измерениями. Не командирский инструмент
дежурства (хрупкий Colab).

### Что это значит для LEGION

Другой продукт. У нас HUD — глаз Three.js (`Scene` / `CyborgEye`), не карта
города. Покрытие PA/антенны мы не считаем (и не должны прикидываться Sionna
без GPU-сцены и калибровки).

**Не брать:** freeze-on-jam, константу −55 дБм, contested-воксели, «цифровой
двойник живой группировки» без телеметрии. **Не обещать** 3D-расстановку РЭБ
в LEGION Control.

Идея, которую достаточно **знать**: карта принятой мощности и правило
поражения должны делить **одни** константы. У них не делят. У нас порог
скана и порог FPGA-детектора уже разведены сознательно и описаны в
`architecture.md` — это как раз та дисциплина, которой SpectralEye не хватает.

## 6. EW-THREAT-DETECTION-SYSTEM (AsaqeLee)

**Репозиторий:** https://github.com/AsaqeLee/EW-THREAT-DETECTION-SYSTEM
**Стек:** Flask, numpy, scipy, Leaflet, Chart.js. MIT. ★ 1.
**Один мелкий коммит** «Patch 03: RANSAC + Multi-start BFGS».

### Что обещает README / README_ZH

Обнаружение и **точное** местоположение источников помех в реальном времени.
Распределённая сенсорная сеть. «Военный» UI. Китайский README обещает
сплав WLS + МНК + центроид.

### Что в коде

**Нет SDR, нет I/Q, нет TDOA/FDOA/MUSIC/AOA.** Восемь словарей в RAM
(«станции» вокруг условного Пекина, сетка ±80 км). Кнопка GENERATE INTEL
сажает случайный источник, считает RSS по log-distance, затем BFGS ищет
точку.

Прямая и обратная модель (симулятор и оценщик **делят** \(P_0, n\)):

\[
P_r(d) = P_0 - 10\,n\log_{10}(d/d_0),\quad
P_0 = 100\,\mathrm{dBm},\ d_0=1\,\mathrm{км},\ n=2
\]

\(P_0=100\,\mathrm{dBm}\) (10 МВт EIRP) как дефолт — физически нелепо.
Цель:

\[
\hat x = \arg\min_x \sum_i \bigl(\hat P_i(x) - P_i\bigr)^2
\]

RANSAC здесь — центроид трёх станций, не подгонка модели. Метод в ответе
всегда строка `"robust_bfgs_ransac"`; `/api/system_status` врёт
`'algorithm': 'least_squares'`. WLS/центроид как голосование **нет**.

«Уверенность» = `clip(100 - residual/N)` — не CRLB. При неверном \(P_0\)
ошибка улетает на сотни тысяч км при «confidence» ~98 %.

**Аномалии:** z-score и IQR по вектору мощностей (для пространственного
поля path-loss это некорректная i.i.d. гипотеза). «Distance-based» метод
алгебраически даёт z ≡ 0 (баг: среднее равно самому себе). ML нет.

**«Real-time»:** клики HTTP. Единственный таймер — `setInterval(..., 30000)`
на статус. CONTRIBUTING сам помечает streaming как несделанное.
«INPUT REAL DATA» — вставка чисел руками, не Soapy.

Тесты `tests/test_anomaly.py` и `test_location.py` на текущем коде **падают**
(неверный ключ результата; \(P_0\) в фикстуре 0, у алгоритма 100).

### Честные ограничения

С одного ноутбука и одного SDR **нельзя** получить координаты постановщика.
Нужны ≥3 разнесённых, опросимых приёмника с известными координатами, калибровка
абсолютной мощности или совместная оценка \(P_0\), и честная ковариация.
Даже тогда RSS — слабый метод по сравнению с TDOA/AOA на синхронизированных
решётках.

### Что это значит для LEGION

Скан LEGION отвечает на вопрос «**на какой частоте** есть энергия над порогом»,
не «где в городе передатчик». Один bladeRF на столе даёт частоту и мощность
в своём приёмнике. Геолокация — другой контур (несколько шлюзов, синхронизация,
калибровка). Рисовать на карте «точку помехи» из одного спектра — та же
ложь, что у них «TRIANGULATE TARGET».

**Не брать:** Leaflet-косплей, 100 дБм, фейковый %, ручной CSV как «реальные
данные». **Не добавлять** вкладку «пеленг» без железа пеленга.

## Карта на тракт LEGION

Текущий контур, с которым сравнивали (не меняется этим документом):

```
SCAN RX (Welch, порог над шумом)
  → pickStrongest / pickPriorityTarget / pickTurnTarget
  → handoff LO → FPGA lb_gated  (или host TX волны)
```

| Идея из разбора | Статус относительно LEGION |
|---|---|
| Жадно брать сильнейший пик | **Уже есть** (ПРИОРИТЕТ) |
| Очередь живых с выдержкой | **Уже есть** (ОБЫЧНЫЙ) |
| Скоринг пика не только по мгновенному dBm (устойчивость, запас над полом) | Имеет смысл как **будущая** эвристика оркестратора; не RL |
| Сопровождение бина между кадрами | Частично: `mergeDetections` по частотному бину |
| MUSIC / MVDR / null-steering | Нужна решётка. Сейчас железа нет → не делать |
| Табличный / глубокий RL «anti-jam» | В разобранных репо либо фейк, либо бумажный дамп. Не внедрять |
| Смешанный хоп как стимул | **Уже есть** HOP/СЛУЧАЙНАЯ с seed |
| 3D карта покрытия / «kill» | Другой продукт; не наш генератор |
| Геолокация постановщика | Нужны N приёмников. Один скан частоты ≠ точка на карте |
| Модули «глушилка / spoof GPS» из симуляторов | Заглушки или вне compliance. **Не копировать** |

### Что сознательно не делаем

1. Не переносим код ни одного из шести репозиториев в `app/`, `firmware/`,
   `fpga/`, `tools/`.
2. Не добавляем в UI подписи «ИИ / MUSIC / CFR / цифровому двойнику», пока
   за ними нет тракта, который это слово означает.
3. Не моделируем GPS spoofing и не пишем процедуры постановки помех — см.
   [compliance.md](compliance.md).
4. Не рисуем карту «источник помехи» из одного спектра.

### Если когда-нибудь расширять оркестратор сканера

Единственное место, где разбор **может** дать конструктив без смены железа:

в `pickPriorityTarget` учитывать не только `rival.powerDbm > heldP`, но и
гистерезис (чтобы не дёргаться на 0.2 дБ) и возраст бина (вспышка на один
dwell vs пик, живущий N кадров). Это эвристика, юнит-тесты, без нейросети.
Пока — **не в этом PR**: документ аналитический.
