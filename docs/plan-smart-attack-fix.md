# Поправка к плану v3 — иерархия aim

Это не новый продукт. Это закрытие дыр, которые v3 назвал и оставил. Код не пишется, пока таблица §1 и контракт §2 не утверждены.

База та же: `origin/main` после #85 / #86. Факты ниже — из `legion_cmds.c`, `legion_fft_peak.vhd`, `legion_fft_channelize.vhd`.

---

## 0. Что v3 оставил сломанным

v3 сказал: Phase 0 может жить на `CH_ENERGY`, Phase 3 «потом» добавит `CH_PWR`, а `legion_ch_elrs_mark_slot` «не красить как разрешение aim». Это недомолвка.

На `main` aim уже стреляет так:

1. `legion_ch_pick` выбирает **слот** 10 МГц по `CH_ENERGY[i] ≥ CH_THR`.
2. `legion_ch_apply` пишет в `CH_TARGET` **`legion_ch_bin[slot]`** — это `g_bin` HDL: argmax бина **внутри слота**, не центр канала сетки.
3. HOLD (`legion_fft_walk` ~1824–1837) **не перецеливается**, пока энергия слота жива. Хоп ELRS на соседний 1 МГц в том же слоте оставляется со старым бином.
4. `legion_ch_elrs_mark_slot` при живом слоте зажигает **все ~10** бит ELRS в `ACTIVE_1..3`. Маска врёт.
5. `CH_PWR` нигде в NIOS не читается. Gate «для 80-сетки CH_PWR≥THR» из v3 — прокси, которого нет.

Пока это так, Phase 3 гейтит по мнимым данным, даже если LUT честный.

---

## 1. Иерархия — одна, без прокси

Четыре уровня. Каждый имеет своего хозяина, свои единицы, свой регистр. Нижестоящий не имеет права целиться, пока вышестоящий не выбран.

```
TILE (плитка взгляда)
  └ score: occupancy НАСТОЯЩЕЙ сетки, пересекающей look
     SLOT (грубая ячейка ≥10 МГц)     — только если native step сетки ≥ 10 МГц
        └ CHANNEL (ячейка сетки)      — всегда, если сетка есть
           └ BIN (CH_TARGET)          — центр канала, не argmax слота
```

| Уровень | Кто считает | Единицы | Регистр | Кто пишет CH_TARGET | Запрещено |
|---|---|---|---|---|---|
| **TILE** | NIOS survey PASS | count живых ячеек сетки за look 5 мс | внутренний `survey_score[]` | никто | `max(peak.mag)`, `next_after` |
| **SLOT** | HDL `g_acc` / `CH_ENERGY_0..7` | Σ (I²+Q²) по бинам слота, uint32 | 0x3D–0x44, порог **0x35 `CH_THR`** | только если native step ≥ 10 МГц | использовать на ELRS 1 МГц и на 5.8 |
| **CHANNEL** | HDL `CH_PWR` + LUT | Σ mag[31:16] за кадр, snap uint16 | mux 0x2D + `CH_IDX`, порог **0x58 `CH_PWR_THR`** | да: argmax живых каналов | `LUT≠0xFF` без энергии; маска `mark_slot` |
| **BIN** | NIOS формула | signed FFT-бин | 0x37 `CH_TARGET` [7:0], [31]=aim | `bin = center(f0+ch·step)` | `g_bin[slot]`, live `peak_word` |

### 1.1 Кто на каком kind

| `GRID.kind` / preset | TILE score | SLOT | CHANNEL | BIN |
|---|---|---|---|---|
| `fhss-narrow` (ELRS/mLRS, step 1 МГц) | count `CH_PWR[ch] ≥ CH_PWR_THR` | не участвует | `CH_PWR[0..n)` | центр канала |
| `ism8` / `ofdm-wide` step 10 МГц на 2.4 | count `CH_ENERGY[s] ≥ CH_THR` по слотам сетки | слот = канал | можно не читать 80 | `g_bin[s]` допустим: ячейка и есть 10 МГц |
| `droneid-zc` / O4-вид 5.8 | count `CH_PWR[ch] ≥ CH_PWR_THR` по LUT 3 центров | **запрещён** (геометрия 2400) | LUT O4VID3 или параметрический | центр выбранного из 3 |
| analog / cw | TILE = max energy в look, без сетки | нет | нет | live peak, режим не «умный» |
| сетка пустая (`n=0` или `f0=0`) | §5.3 fallback | нет | нет | нет aim |

### 1.2 Единицы порогов — два числа, не одно

Факт. `CH_ENERGY` в `legion_fft_peak.vhd` суммирует полный `mag = I²+Q²` (32 бит) в `g_acc`. `CH_PWR` суммирует `mag(31 downto 16)` в 24-бит `acc` и отдаёт sat16. Один `CH_THR` на оба — размерность врёт.

| Регистр | Адрес | Ширина | Чего порог |
|---|---|---|---|
| `CH_THR` | 0x35 | uint32 | слот `CH_ENERGY` (только kind с step ≥ 10 МГц на 2.4) |
| `CH_PWR_THR` | **0x58 новый** | uint16 в [15:0] | канал `CH_PWR` |
| `CH_HYST` | 0x36 | uint32 | N кадров подряд на **том уровне, которым целимся** (канал для 1 МГц, слот для 10 МГц) |

`CH_THR=0` больше не значит «суммируй всё как будто сетка есть». Ноль на неиспользуемом уровне = уровень выключен. Для умной атаки с 1-МГц сеткой: `CH_PWR_THR ≠ 0`, `CH_THR` игнорируется.

## 2. Контракт aim — закрыть `mark_slot`

### 2.1 Удалить покраску

`legion_ch_elrs_mark_slot` и вызов из `legion_ch_update_hits` — **вырезать**. Комментарий «10 МГц кроет ~10 хопов, пик один не есть маска» остаётся верным как предупреждение: маска слота не есть маска каналов.

`ACTIVE_0` (8 бит слотов) можно оставить как отладку 2.4 / 10 МГц.

`ACTIVE_1..3` (80 бит ELRS) писать **только** из `CH_PWR[ch] ≥ CH_PWR_THR`. Иначе держать 0. Хост/UI, который читает эти биты, больше не видит 10 фантомов.

### 2.2 Pick канала, не слота

Новая функция, одна на stare и на survey score:

```
legion_ch_read_pwr(n):
    for ch in 0 .. n-1:
        poke CH_IDX = ch
        w = mux CH_PWR
        pwr[ch] = (w >> 8) & 0xffff     // как слово канала в HDL

legion_ch_pick_channel(n):
    best = none
    for ch in 0 .. n-1:
        if pwr[ch] < CH_PWR_THR: continue
        if pwr_hits[ch] < CH_HYST: continue
        if LUT не содержит этот ch (ни один бин не мапит): continue
        best = argmax pwr, ничья → меньший ch
    return best

legion_ch_center_bin(ch):
    f_hz = GRID_F0_HZ + ch * GRID_STEP_HZ     // или пресет
    off  = f_hz - look_lo_hz
    k    = round(off * 256 / fs)              // signed
    return k & 0xff

legion_aim_to_channel(ch):
    bin = legion_ch_center_bin(ch)
    if Gemini bypass: write_target(bin) без bit31
    else aim_set(bin)
```

`pwr_hits[80]` — SRAM NIOS, не новые PIO. На кадре: `pwr≥thr → ++hits`, иначе 0. Как слотовые `ch_hits`, но по каналу.

### 2.3 HOLD больше не «держит слот»

Текущее (факт):

```1824:1837:fpga/nios/legion_cmds.c
            if (slot < LEGION_CH_SLOT_N &&
                legion_ch_e[slot] >= legion_ch_thr &&
                legion_ch_hits[slot] >= need) {
                ...
                return;   /* CH_TARGET не меняем */
            }
```

Заменить для 1-МГц сетки:

```
каждый тик карты (период ≥ SETTLE, как сейчас):
    read_pwr(n)
    update pwr_hits
    ch = pick_channel(n)
    if ch is none → цель погасла → channel_scan / resurvey, не держать старый бин
    if ch != current_ch → aim_to_channel(ch)   // PLL не трогать, DRFM не сбрасывать
    else оставить CH_TARGET
```

Для 10-МГц сетки на 2.4 слотовый HOLD остаётся законным: ячейка и есть слот, `g_bin[s]` обновлять если argmax слота сменился.

### 2.4 Откуда BIN никогда больше не берётся в умной атаке

| Источник | Сейчас | Умная атака |
|---|---|---|
| `g_bin[slot]` / `CH_BINS_*` | `legion_ch_apply` | только kind step ≥ 10 МГц @ 2.4 |
| `peak_word[7:0]` | `legion_fft_fire`, `survey_lock_fire` | запрещён, если сетка жива |
| `center(f0+ch·step)` | нет | **единственный** путь для 1 МГц и для O4-центров |

## 3. 5.8 — отдельная ветка, не «та же ISM-восьмёрка»

### 3.1 Факт: текущая occupancy на 5.8 мертва

`ch_slot` в `legion_fft_peak.vhd` и `legion_ch_slot_of_bin` зашиты в `LEGION_OCUSYNC_F0_KHZ=2400000`, полоса 80 МГц. На 5768 МГц оба возвращают −1 / `0xFF`. `g_acc` не копится, `CH_ENERGY=0`, HOLD считает цель мёртвой каждый тик.

Пресет `O4VID3` (5768.5 / 5789.5 / 5814.5) жив только в `legion_ch_map_bin` → LUT → `CH_PWR`. Это уже другая ветка, просто к ней не подключён ни survey pick, ни aim pick.

xA4 5.8 физически видит (каталог 70–6000). Ветка нужна не потому что «плата не достаёт», а потому что **карта 2400 не переносится**.

### 3.2 Три параллельных контура (не один if)

| Контур | Полоса | Матчер (Фаза L) | LUT / preset | Occupancy | Aim |
|---|---|---|---|---|---|
| **S24** | 2400–2480 | step/n_used/ELRS+mLRS, якорь 2400.4 / 2401 | ELRS 80×1, ISM8 8×10, или 0x51–0x53 | 1 МГц → `CH_PWR`; 10 МГц → `CH_ENERGY` | §2 |
| **C58 digital** | 5725–5850 (xA4/xA9 only) | ширина 10/20/40 + **ZC 600/147** → `droneid-zc`, иначе `ofdm-wide` | `O4VID3` (3 центра) или параметрический n≤3, f0/step с карточки | **только `CH_PWR`** | центр выбранного из n |
| **C58 analog** | таблицы A/B/E/F/R | гребёнка PAL, не ZC | сетки нет | нет | live peak / не умная |

x40 / ADF4351: контуры C58 в UI не предлагаются (потолок железа). Не «потом на той же плате».

Запрещено:

- Кормить 5.8 в `ch_slot` / `CH_ENERGY` / `mark_slot`.
- Ставить `LEGION_CH_MODE_OCUSYNC` на 5.8.
- Один ARM на коридор 2400–5800 (один LO, analog ≤ 56 МГц).
- Имя «O4 борт» без ZC.

### 3.3 Что сделать в коде (5.8 ветка)

Хост, Фаза L:

- Если центр слуха ≥ 5.1 ГГц — не звать `classify_fhss_domain` как основной путь. Звать ширину + analog-гребёнка + `droneid.py` ZC.
- Карточки: `droneid-zc` / `ofdm-wide` / `analog` с полем `band=c58`.
- Confirm пишет `kind` + `O4VID3` или `GRID_F0/STEP/N` (n≤3). Не пишет ELRS 2400.4.

NIOS:

- Если `GRID_F0_HZ ≥ 5e9` или preset `O4VID3`: survey score и aim pick **только** через `CH_PWR`. Ветку `CH_ENERGY` / `slot_in_look` не вызывать.
- `legion_ch_rebuild_lut` уже умеет O4VID3 — оставить. Параметрический путь 0x51–0x53 тот же, n=3.
- `ch_slot` HDL не обобщать на 5.8 в v1 (чужая геометрия, риск сломать 2.4). Просто не читать.

## 4. Мелочи — контракты, не «не забыть»

### 4.1 Сброс `CH_TARGET` на analog hop

Уже есть: `legion_fft_enter_search` после успешного hop вызывает `legion_aim_clear` и `legion_ch_push_lo_fs` (LUT перестраивается под новый LO).

Дырка: сразу после hop `legion_fft_fire` / `survey_lock_fire` делают `aim_clear` и **тут же** `aim_set(peak_bin)`. На новой плитке прицел = глобальный пик, не канал сетки.

Контракт умной атаки, сетка жива:

```
enter_search:
    hop
    aim_clear
    zero pwr_hits[80], ch_hits[8], ACTIVE_*
    push_lo_fs + rebuild LUT
    snap_have = false          // ждать first-valid

FRAME после hop:
    не звать fft_fire / survey_lock_fire по peak
    копить CH_PWR (или CH_ENERGY, если kind 10 МГц @ 2.4)
    когда pick_channel дал ch → aim_to_channel(ch)
```

Если hop **не** удался — aim уже снят (текущий порядок: clear после успеха; при отказе clear не вызывается, FTW старого LO жив). Контракт: при отказе hop тоже `aim_clear`, индекс не продвигать (уже так).

Тест: hop 2428 → 2472, `CH_TARGET` читается 0 до первого валидного кадра с `CH_PWR≥thr`; затем бин центра канала новой плитки, не бин старой.

### 4.2 Два порога

См. §1.2. Хост после confirm:

- ELRS/mLRS: писать `CH_PWR_THR` (калибр / дефолт из лаборатории), `CH_THR=0` (слот выключен).
- ISM8 / ofdm-wide 10 МГц @ 2.4: писать `CH_THR`, `CH_PWR_THR=0`.
- O4 / 5.8: писать `CH_PWR_THR`, `CH_THR=0`.

Дефолт `CH_PWR_THR` не равен дефолту `CH_THR`. В шлюзе два поля: `ch_thr`, `ch_pwr_thr`. Не переиспользовать `ch_thr`.

### 4.3 Fallback при пустой сетке

Пустая = `GRID_META.n==0` или `GRID_F0_HZ==0` и preset `MANUAL`.

| Что делает | Запрещено |
|---|---|
| PASS крутится, score = max mag (как сейчас `survey_mag`) | считать `CH_ENERGY` 2400 «сеткой» |
| Stare = обычный `fft_fire` на пик, **без** `aim_en` (LIVE) | писать ELRS ACTIVE, звать `mark_slot` |
| UI: «сетка не собрана — это не умная атака» | молча встать в ELRS preset |

`unknown` после матчера без выбора оператора = пустая сетка, не «поставь ELRS 80».

### 4.4 `window_limited` в ARM

Сейчас флаг живёт только в JSON `fhss_detect.py`. v3 положил его в `GRID_FLAGS[0]` и не сказал, что делает NIOS.

Контракт:

- Хост пишет `GRID_FLAGS.window_limited` и `f0_unconfirmed`.
- Если оба истинны: PASS **не** входит в stare после первого прохода. Нужен второй проход по оставшимся плиткам (score обеих) **или** хост сбрасывает `f0_unconfirmed` (оператор принял номинал).
- LUT на плитке мапит только бины **текущего look**. Каналы сетки вне look → `0xFF`, в `CH_PWR` не копятся (HDL уже так: `ch < n_ch` и unmapped 0xFF).
- Если оператор подтвердил f0 — флаг снят, stare разрешён с первой победившей плитки, абсолютный LUT законен.

Тест: одна плитка 2428–2483, ELRS, `f0_unconfirmed=1` → нет stare, есть второй PASS. После записи флага 0 → stare на pick.

### 4.5 Gemini

Факт. `legion_dual_from_peak1`: два валидных пика одного кадра, циклическая дистанция ≥ 16 бинов → `XLAT_BYPASS`, `xlat_bypass_auto`. `aim_set` не вызывается (`write_target` без bit 31). Когда второй тон пропал — bypass снимается.

Контракт умной атаки — не ломать это:

- Два тона ≥ `fs/16` (~3.5 МГц, Gemini ~40 МГц = n/2) → окно MA-16 не удерживает оба. TX = вся плитка, прицел снят.
- UI: «два тона в взгляде, окно 3.5 МГц не покрывает, aim off».
- Не целиться в один близнец (второй умрёт в стоп-зоне).
- Не писать `CH_TARGET[31]` пока `bypass_auto`.
- Сетка и `CH_PWR` продолжают копиться — когда останется один тон, aim возвращается через `pick_channel`, не через live peak.

## 5. Регистры — дельта к v3

v3: сетка 0x51–0x57, `MAX=0x50` сейчас. Добавить:

| Адрес | Символ | Packing |
|---|---|---|
| 0x58 | `CH_PWR_THR` | [15:0] uint16 порог канала; [31:16] 0 |
| 0x59 | `AIM_CH` | STATUS: [7:0] текущий канал сетки (0xFF=нет); [31]=armed. Не путать с `CH_TARGET` (бин) |

`LEGION_REG_MAX = 0x59`.

`GRID_FLAGS` как в v3, плюс смысл ARM в §4.4. `kind=4` (`droneid-zc`) и полоса из `f0` выбирают контур §3, не отдельный бит.

## 6. Фазы — что меняется относительно v3

Порядок тот же: L → 0 → 1 → 2 → 3. Меняется содержимое 0 и 3. Фазы 4 по-прежнему нет.

**Фаза 0** больше не «можно начать с восьмёрки `CH_ENERGY`».

- Сетка 1 МГц или 5.8: score плитки = count каналов `CH_PWR≥CH_PWR_THR` за look. Чтение 80 (или n≤3) mux за кадр. Без этого pick снова max-mag / слот.
- Сетка 10 МГц @ 2.4: score = count `CH_ENERGY≥CH_THR`.
- Пустая сетка: max mag, и это не называется умной.
- `next_after` убрать.

**Фаза 2** как в v3 (0x51–0x57) **плюс** 0x58/0x59, плюс хост пишет правильную пару порогов (§4.2), плюс `window_limited` в ARM (§4.4).

**Фаза 3** не стартует, пока нет `read_pwr` + `center_bin` + вырезанного `mark_slot`. Иначе снова гейт по слоту.

- HOLD/stare: §2.3.
- Hop: §4.1.
- Gemini: §4.5.
- 5.8: только контур C58, без `CH_ENERGY`.

**Фаза L** для 5.8 — отдельный матчер (§3.3), не «та же карточка ELRS на другой частоте».

## 7. Приёмка этой поправки

Без этих тестов дырка не закрыта.

1. **Слот ≠ канал.** В одном 10-МГц слоте живой ELRS-хоп на канале k, CW на краю слота сильнее. `CH_TARGET` = центр канала k (по `CH_PWR`), не `g_bin` CW. `ACTIVE_1..3` — один бит, не десять.
2. **Хоп внутри слота.** Канал k → k+3 (3 МГц) в том же слоте. После `CH_HYST` кадров `CH_TARGET` переезжает на центр k+3. Analog LO не прыгает.
3. **Слот погас.** Все `CH_PWR` ниже порога → aim снят, не держится старый бин из-за остаточной `CH_ENERGY`.
4. **Hop плитки.** 2428 → 2472: `CH_TARGET=0` до first-valid; LUT перестроен; старые `pwr_hits` нули.
5. **Пустая сетка.** `f0=0`, n=0 → нет ACTIVE ELRS, нет `aim_en`, pick = max mag, UI не пишет «умная».
6. **`window_limited`.** Одна плитка, флаг 1 → нет stare. Флаг снят оператором → stare есть.
7. **5.8 xA4.** LO 5789.5, preset O4VID3: `CH_ENERGY` игнорируется (нули не считаются «пусто»). Aim на один из трёх центров по `CH_PWR`. На x40 коридор 5.8 → отказ.
8. **Gemini.** Два тона ≥ 16 бинов → bypass, `CH_TARGET[31]=0`. Один тон остался → aim с `pick_channel`.
9. **Два порога.** Запись `CH_THR` не меняет gate 1-МГц сетки. Запись `CH_PWR_THR` не меняет gate ISM8.

## 8. Что не делается в этой поправке

- Обобщать HDL `ch_slot` на произвольный f0 (5.8 и кастом). v1 обходит веткой `CH_PWR`.
- Walk / `PROTO_PERIOD`.
- Имя OcuSync без ZC.
- Один LO на 2.4+5.8.
- HDL-аккумулятор `CH_PWR` на секунды.

## 9. Итог

v3 правильно снял max-mag, зарубку и walk. Прицел он оставил на **среднем по слоту**: `CH_ENERGY` выбирает 10 МГц, `g_bin` целится, `mark_slot` врёт маске, `CH_PWR` не читается, 5.8 смотрит в карту 2400.

Исправление одно: **TILE → CHANNEL → BIN**. Слот — опция только для 10-МГц сетки на 2.4. `CH_TARGET` = центр канала. `mark_slot` удалить. 5.8 — свой матчер и свой LUT, свой occupancy = `CH_PWR`. Два порога. Hop сбрасывает aim и не зажигает его с пика. Пустая сетка честно не умная. `window_limited` держит stare. Gemini снимает aim, не один близнец.
