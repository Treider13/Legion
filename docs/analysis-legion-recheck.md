# LEGION — независимый разбор углублённой перепроверки и плана

Снимок: `c213041` (`c2130417…` в отчёте перепроверки — тот же merge
`#32`). Исходники и прошивку платы этот разбор не меняет.

Вопрос, на котором остановилась перепроверка: **утвердить работу с
исходниками и тестами без прошивки платы на данном этапе?**

**Вердикт: да, с уточнениями.** Этапы 1–7 плана — правильное направление.
Этапы 8–9 (сборка xA4 и стендовая приёмка конкретного образа) остаются
отдельным железом и в эту фазу не входят. Частоту внутри окна обещать
нельзя ни после этой фазы, ни после перечисленных исправлений.

Ниже — что подтверждено чтением кода этого снимка, что является пробелом
контракта, а что план должен изменить, прежде чем трогать поведение.

---

## 1. Что система обещает и чего она заведомо не делает

Замысел FPGA-режима («Автоматический перехват») зафиксирован в
`fpga/README.md` и `fpga/nios/legion_cmds.h`:

- после Старта хозяин — плата;
- USB не участвует в круге «энергия → TX»;
- детектор — окно средней \(I^2+Q^2\), не FFT;
- TURN: выдержка от первого `det_active`, затем следующий взгляд;
- выдержка может быть 0.4 мс (`SCAN_DWELL_US = 400`).

Это **не** спектроанализатор и **не** измеритель точной частоты внутри
взгляда. Водопад в FPGA-режиме — композит «LO + гейт» (`applyLook` /
`fpgaLookEnergy` в `app/src/sense/waterfall.ts`), не измеренный спектр.
400 мкс в регистре — единица счётчика tamer, не доказанная длительность
физического выхода. Нагрузка 50 Ом в модели принята подключённой;
модель усилителя и допустимые мощность/полоса нагрузки неизвестны.

Перепроверка правильно отделяет программные ошибки от измерений на SMA.
Этот разбор делает то же.

## 2. Подтверждённые программные дефекты

Все пункты ниже воспроизводимы из исходников. Аппаратная мощность на
выходе ими не измеряется.

### 2.1 Валидация ARM слишком поздняя — тракт уже под током

В `fpga/host/legion_gateway.py` порядок ARM:

1. порог / watchdog / NCO;
2. `_air_enable()` — на micro пишет AIR_* и `AIR_PREP` (RX+TX);
3. `_program_scan()` — здесь отказ «нужны `scan_f1_mhz` и `scan_f2_mhz`»;
4. запись `CTRL.ARM`;
5. откат эфира — **только** если шаг 4 не удался и живого ARM не было.

Отказ на шаге 3 возвращает `ok:false` и **не откатывает** шаг 2. Флаги
`_rx_by_us` / `_tx_by_us` уже включены, `AIR_PREP=7` уже ушёл в NIOS.

Существующий тест это маскирует:

```1125:1127:fpga/test/test_legion_fpga.py
r = rpcm({"op": "arm", "mode": "lb_gated", "det_thr": 5000,
          "freq_mhz": 2414.0, "scan_enable": True})
check("micro: scan_enable без коридора → отказ", r.get("ok") is False)
```

Проверяется только код ответа. Состояние тракта после отказа не читается.
Это ровно тот «ложный успех», о котором говорит перепроверка.

### 2.2 Частичный отказ `legion_air_up` не гасит уже включённое

`legion_air_is_up = true` ставится только в самом конце успешного
`legion_air_up`. Если RX enable прошёл, а TX enable/unmute отказал,
флаг остаётся ложным. Тогда `legion_air_down()` делает:

```221:223:fpga/nios/legion_cmds.c
    if (!legion_air_is_up) {
        return true;
    }
```

Очистка сообщает успех и **не посылает STANDBY**. На чипе RX (и, при
частичном TX) может остаться включённым.

### 2.3 DISARM глотает отказ RFIC

```659:662:fpga/nios/legion_cmds.c
            if ((data & 0x1) == 0 && legion_air_is_up) {
                /* DISARM: эфир гасим сами — шлюз про RFIC не знает */
                legion_air_down();
            }
```

Возврат `legion_air_down()` игнорируется. Дальше PIO пишется и функция
возвращает `true`. Хост (`op disarm`) считает CTRL=0 достаточным
подтверждением. Неподтверждённое выключение выглядит как успех.

### 2.4 Отказ перестройки TX снимает mute на рассогласованных LO

```429:440:fpga/nios/legion_cmds.c
    if (!rfic_command_write_immed(BLADERF_RFIC_COMMAND_FREQUENCY,
                                  BLADERF_CHANNEL_RX(0), freq_hz) ||
        !rfic_command_write_immed(BLADERF_RFIC_COMMAND_FREQUENCY,
                                  BLADERF_CHANNEL_TX(0), freq_hz)) {
        (void)rfic_command_write_immed(BLADERF_RFIC_COMMAND_TXMUTE,
                                       BLADERF_CHANNEL_TX(0), 0);
        return false;
    }
```

Если RX перестроился, а TX нет: mute снимается, RX и TX на разных
частотах, walker считает hop неудачным и откатывает только индекс сетки,
не частоты чипа.

### 2.5 Чтение SCAN_* возвращает STATUS, не записанные параметры

`legion_reg_read` отдаёт статики только для `AIR_PREP` / `AIR_FREQ` /
`AIR_FS` / `AIR_BW`. Адреса `SCAN_F1`…`SCAN_DWELL_US` падают в общее
чтение STATUS-PIO. Хост-тесты этого не ловят: они смотрят
`gw_m.fpga._t.regs` (словарь записей FakeTransport), а не протокол чтения.
Сам FakeTransport на чтении SCAN тоже синтезирует STATUS — модель и NIOS
совпадают в ошибке, поэтому набор зелёный.

Шлюз не имеет `op get`. Единственный readback коридора — косвенный
(`status.freq_mhz` из `AIR_FREQ`). Записанные F1/F2/dwell обратно не
проверить.

### 2.6 Прямая команда выдержки `0,4 мс` → запись `0`, ответ успех

Два независимых канала:

1. `op set`, `reg=scan_dwell_ms` отображён на **тот же** регистр
   микросекунд, без ×1000. `val = int(msg.get("value") or 0)`:
   `int(0.4) == 0`. Ответ `ok:true`. В NIOS `0` значит «дефолт 3 с», не
   «0.4 мс».
2. UI `parseFloat("0,4") === 0` → `fpgaTurnDwellClamp(0)` подставляет
   дефолт **3000 мс**, не 0.4. Европейская запятая не «тихо 0», а тихо
   три секунды. Это другой, не менее опасный исход.

Комментарий шлюза («0.4 мс оператора не должен стать 0 и дефолтом NIOS
3 с») закрывает только путь `scan_dwell_ms: 0.4` внутри `op arm`, не
`op set` и не запятую в поле UI.

### 2.7 FIR для низкого sample-rate в прямом NIOS-пути отсутствует

Nuand (`bladerf2_set_sample_rate`,
[bladerf2.c:1089](https://github.com/Nuand/bladeRF/blob/35174c30b009cdb335800c411f3c14d45283f12b/host/libraries/libbladeRF/src/board/bladerf2/bladerf2.c#L1089))
для диапазона `bladerf2_sample_rate_range_4x` (**520834…2083334** Гц)
включает RX FIR DEC4 и TX FIR INT4 **до** записи частоты отсчётов.

Тот же диапазон лежит в нашем вендоренном
`fpga/vendor/bladerf/fpga_common/include/bladerf2_common.h`. Значит
замечание относится **и к окну 2 МГц** (`airFsHz(2) = 2_000_000 < 2083334`),
не только к 0.2 МГц (`520834`).

`legion_air_up` пишет `SAMPLERATE` / `BANDWIDTH` и не пишет
`BLADERF_RFIC_COMMAND_FILTER`. Штатный NIOS-путь FILTER уже есть
(`devices_rfic_cmds.c`); пример Nuand foxhunt ставит DEC4/INT4 до
SAMPLERATE. Legion этот шаг пропускает.

Это **подтверждённый пропуск в коде**. Это **не** измеренный отказ платы.
Нижнюю границу 0.2 МГц объявлять невозможной оснований нет. Объявлять её
рабочей после одной записи `AIR_FS_HZ` — тоже нельзя.

## 3. Контракт, а не обязательно дефект реализации

### Одно окно + выдержка 400 мкс

`legion_scan_walk` при `n == 1` возвращается сразу: dwell/TURN не
применяются, LO не шагает, гейт \(I^2+Q^2\) живёт, пока есть энергия.
Через секунду модельного времени ARM сохраняется — так написано в
комментарии к этой ветке.

Замысел README («нашёл → выдержка → следующий взгляд») для одного окна
не определён: следующего взгляда нет. Тест NIOS покрывает TURN hop только
при нескольких стоянках. Это пробел **продуктового контракта**, его нужно
зафиксировать до кода: либо «в одном окне TX следует за энергией, dwell
не гасит», либо «после dwell mute даже при живом det». Сейчас реализация
делает первое, а операторский текст намекает на второе.

## 4. Почему существующий ALL PASS недостаточен

| Набор | Что доказывает | Как даёт ложный успех |
|---|---|---|
| `nios_work_test.c` | порядок mute, GAINMODE, happy-path SCAN | `rfic_command_write_immed` всегда `true`; нет TX-fail, DISARM-fail, частичного AIR |
| `test_legion_fpga.py` | протокол шлюза, откат при сбое CTRL | отказ SCAN без коридора не проверяет AIR_PREP; SCAN читается из словаря записей |
| FakeTransport | упаковка пакетов | нет журнала RFIC; чтение SCAN = STATUS; DISARM всегда успешен |
| GHDL 8/8 | цифровые блоки при идеальных тактах | не RFIC, не USB, не Quartus timing |
| E1–E6 | канал, NCO, плеер, det_count, wd_fired | E2 при отсутствии кабеля — SKIP, не FAIL; E6 = ping после power cycle, не сверка bitstream/timing |
| UI-тесты `airFsHz(0.2)` | хост выбирает 520834 | не доказывают FILTER на NIOS |

Критерий честного теста на этом этапе: отказ обязан оставлять тракт в
известном безопасном состоянии; успех обязан читаться тем же протоколом,
которым пользуется хост, а не внутренним словарём модели.

## 5. Что остаётся принципиально незакрытым

Эти пункты перепроверка назвала верно. Исправления 1–7 их не закроют:

1. Онбордовый детектор не даёт частоту внутри окна.
2. 400 мкс регистра ≠ доказанная длительность RF на SMA.
3. FPGA-водопад — визуализация обнаружения, не спектр.
4. Старый отчёт xA4 с отрицательными запасами не доказан как отчёт
   загруженного образа. В репозитории свежего timing-отчёта нет.
5. 50 Ом — допущение стенда, не модель PA.
6. Heartbeat уже идёт toggle → двойной триггер → фронт
   (`legion_regs.vhd`). Слепой перенос ADI `sync_event` / `sync_bits` не
   нужен. Открытый CDC — многобитный `det_count` с rx в tx на x40
   (это уже сказано в комментарии того же файла). Аудит — да;
   замена heartbeat — нет, пока аудит не покажет дыру.

## 6. Что брать с GitHub, а что не брать

Готовой замены кастомной ревизии `legion` нет. Брать по файлам:

| Источник | Зачем | Ограничение |
|---|---|---|
| Nuand `bladerf2_set_sample_rate` + `BLADERF_RFIC_COMMAND_FILTER` | FIR DEC4/INT4 и возврат к default | Команды уже в нашем NIOS; не тянуть весь host USB-стек |
| Nuand foxhunt (`FILTER` до `SAMPLERATE`) | локальный эталон порядка | Другая задача (768 кГц тон), не замена AIR_PREP |
| Readback `SAMPLERATE`/`BANDWIDTH`/`FILTER` | «записали ≠ применили» | Нужны отказы, не только лог |
| Tone generator / micro-пример | лабораторный формат отсчётов | После появления стенда, не в этой фазе |
| VUnit | по желанию | GHDL-набор уже есть; не блокер |
| ADI `sync_event` | только если CDC-аудит докажет нужду | Не кандидат «закрыть этап 5 целиком» |

Не копировать libbladeRF host-путь как замену NIOS AIR: хост при закрытии
handle сам гасит RFIC — именно поэтому Legion поднимает эфир на NIOS.

## 7. План: что утверждается и что меняется

Утверждается **фаза «исходники + тесты, без прошивки платы»**.

Порядок перепроверки в целом верен: сначала критерии и честные тесты,
потом поведение, потом шина/единицы, железо — отдельно. Ниже — та же
нумерация с обязательными поправками.

### Этап 1. Зафиксировать версию и критерии — утвердить

Заморозить `c213041` как базу. Локальные незакоммиченные правки (если
появятся) не смешивать с этой фазой. Записать контракт:

- отказ ARM/DISARM/tune не оставляет тракт «как получилось»;
- неизвестное состояние явно видно хосту (`unknown` / не `ok`);
- 0.2 МГц — заявленный минимум BW, не обещанный рабочий режим, пока нет
  FILTER + readback + стенд;
- одно окно + TURN — явное правило (см. §3);
- частота внутри окна — вне этой фазы.

### Этап 2. Достоверность тестов — утвердить, расширить, делать первым

Без этого этапы 3–6 снова зелёные впустую.

Обязательные дыры, которые набор должен начать ловить:

- RFIC-стаб умеет отказывать по команде и каналу;
- после отказного ARM `AIR_PREP` и флаги владения не «подняты»;
- DISARM при отказе STANDBY не возвращает успех;
- hop с отказом TX не unmute и не оставляет разные LO;
- чтение SCAN_* по протоколу = записанное, не STATUS;
- `op set scan_dwell_ms` не пишет микросекунды и не принимает `0.4` как 0;
- приёмка: SKIP кабеля ≠ ALL PASS; неизвестный образ ≠ E6 PASS.

Модель шлюза обязана повторять readback NIOS, а не словарь записей.

### Этап 3. Валидация запуска, откаты, DISARM — утвердить

Высокий приоритет: это управление мощностью, не косметика.

- границы SCAN и единицы dwell — **до** `_air_enable`;
- любой отказ после частичного подъёма — STANDBY / CONTROL off и сброс
  флагов, либо явный `unknown`;
- `legion_air_down` учитывать; DISARM не врать;
- `legion_hop_lo`: при отказе TX не unmute; откатывать RX или держать mute
  и `unknown`;
- хост не должен считать CTRL=0 доказательством погашенного RFIC.

### Этап 4. USB, обратное чтение, повтор после сброса — утвердить

Readback SCAN/AIR/FILTER. После USB reset / nios_reset статики и
«наследство» прошлой сессии уже частично лечатся явной записью 0; это
нужно покрыть чтением, не только записью. Не раздувать до переписывания
всего USB-стека.

### Этап 5. Часы, heartbeat, watchdog — утвердить как аудит, не как перенос

Сначала таблица доменов и что уже синхронизировано. Heartbeat CDC есть.
`det_count` на x40 — известный риск. ADI-примитивы — запасной референс,
не обязательная замена. Watchdog-единицы уже считаются в
`watchdog_limit_for_fs`; проверять согласованность модели и теста, не
выдумывать новый deadman.

### Этап 6. Единицы времени, default, низкий fs, диапазоны — утвердить с рамкой

- починить `scan_dwell_ms` / запятую / `0 → 3 с`;
- добавить FILTER по правилу Nuand 4x **до** SAMPLERATE, с readback;
- не обещать 0.2 МГц «готово» без стенда;
- 2 МГц тоже в зоне 4x — дефолтный park не исключение.

### Этап 7. Форматы, буферы, честность визуализации — утвердить узко

Подписать водопад FPGA как взгляд/гейт. Не строить «спектр» из
`det_active`. Числовые форматы IQ — сверка с уже принятым SC16Q11, не
новый DSP.

### Этап 8–9. Сборка xA4 и стенд — не в этой фазе

Quartus, timing с неотрицательными запасами, сверка bitstream с отчётом,
E1–E6 без SKIP-как-PASS, мощность/полоса на 50 Ом — отдельное решение
после зелёных этапов 1–7. Прошивку платы сейчас не трогать.

## 8. Критерии приёмки этой фазы (без железа)

Фаза закрыта, когда одновременно верно:

1. Отказной ARM с `scan_enable` без границ не оставляет `AIR_PREP` up и
   флаги владения.
2. Частичный AIR и отказ STANDBY видны как ошибка; повторный DISARM
   повторяет гашение.
3. Отказ TX-hop не unmute и не оставляет разные LO без явного `unknown`.
4. Протокольное чтение SCAN_* совпадает с последней успешной записью.
5. `0,4` / `0.4` мс в UI и в `op set` не превращаются в 0 или в 3 с.
6. NIOS-тест с отказывающим RFIC-стабом красный на старом коде и зелёный
   на новом; хост-тест не смотрит внутренний словарь как оракул readback.
7. Документированы: правило одного окна; 0.2 МГц как код-gap FIR, не как
   измеренный отказ; вне скоупа — частота внутри окна, физические 400 мкс,
   спектр водопада, timing xA4, модель PA.

## 9. Ответ на вопрос утверждения

**Да: утвердить работу с исходниками и тестами без прошивки платы.**

Не утверждать без правок: слепой перенос ADI heartbeat; обещание 0.2 МГц
или точной частоты после этапов 1–7; считать текущий ALL PASS критерием
готовности; прошивать xA4, пока нет честных тестов и сверки timing с
образом.

Программу и прошивку этот документ не меняет. Следующий шаг после
утверждения — этап 1 (контракт в тестах/комментариях) и этап 2
(ломающие, но честные тесты), затем поведение 3–6.
