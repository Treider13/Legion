# LEGION — анализ и апгрейд тракта (перепроверено фактами)

Документ фиксирует подтверждённые первоисточниками рекомендации и то, что из
них **внедрено в код** (с тестами), а что остаётся **аппаратным** (вне кода).
Первоисточник по чипу — [ADF4351 Datasheet Rev. A (analog.com)](https://www.analog.com/media/en/technical-documentation/data-sheets/adf4351.pdf).

## Что внедрено в прошивку/ПО (с тестами)

### 1. Выравнивание выходного уровня через PE43702 (рекомендация «ровные 0.1 Вт»)

**Факт.** Дешёвый модуль ADF4351 гуляет по выходной мощности **~9 дБ** по
диапазону 35М–4.4Г ([dd1us.de](https://www.dd1us.de/Downloads/ADF4351%20PLL%20module%20with%20OLED%201v3.pdf)),
хотя сам чип даёт ±1 дБ (даташит, «Output Power Variation ±1 dB»). Чип умеет
лишь 4 грубые ступени −4/−1/+2/+5 дБм (R4[4:3]). PE43702 добавляет 0–31.75 дБ
шагом 0.25 дБ.

**Реализация.** Разомкнутая калибровка «частота → измеренный выход (дБм)»:
- `firmware/include/leveling_math.h` — чистая математика (интерполяция,
  расчёт затухания, upsert таблицы), host-тесты `test/test_leveling` (11 кейсов);
- `firmware/src/leveling.cpp` — состояние + применение через PE43702;
- команды: `CAL LEVEL <fMHz> <dBm>` / `CAL LEVEL CLEAR`, `SET LEVEL <dBm>|OFF`,
  `LEVEL?` (см. [protocol.md](protocol.md)); NVS-персистентность таблицы;
- применяется на каждом шаге коридора и при ручной установке частоты.

**Честное ограничение.** Аттенюатор только **ослабляет** — целевой уровень
обязан быть ≤ минимума измеренного по полосе, иначе затухание упрётся в 0.
Данные калибровки нужно **измерить прибором** (анализатор/измеритель мощности) —
без него выравнивание построить нельзя. Модель **разомкнутая**: она не
компенсирует дрейф от температуры/нагрузки; для этого нужна замкнутая АРУ
(см. аппаратный пункт ниже).

### 2. Fast-scan: delta-запись регистров в коридоре

**Факт.** При перестройке достаточно перезаписать только изменившиеся регистры,
R0 — последним (защёлкивает double-buffered поля и триггерит band select;
даташит «Program Modes»). Приём применён в [tctsui/ADF4351](https://github.com/tctsui/ADF4351)
(`FastScanSetF` — один регистр вместо шести).

**Реализация.**
- `firmware/include/reg_delta.h` — выбор регистров для записи (host-тест
  `test/test_reg_delta`, 5 кейсов): изменившиеся R5..R1 по убыванию + R0 всегда
  последним;
- `Adf4351Driver::writePlanDelta`, `synth_apply_fast`, интеграция в
  `sweep_engine` (первый шаг сессии — полная запись R5→R0, дальше delta).

**Честное ограничение (перепроверено даташитом).** Это срезает только время
SPI-**записи** (~40 мкс → ~7–13 мкс), но **не обходит физику захвата ФАПЧ**
(settling ~0.15–0.5 мс; Hellmich мерил до 1.5 мс). Предел скорости свипа задаёт
петля, а не контроллер. Аппаратный fast-lock (даташит «Fast Lock Loop Filter
Topology», Fig. 31/32) требует вывода **SW (pin 5)** и переделки loop-фильтра
(демпфирующий резистор ÷4, ток CP ×16) — на стоковых модулях SW не выведен,
поэтому здесь **не используется**. Отключение band select для шагов <1 МГц
(R1.DB28) действует лишь около одной точки («<1 MHz от изначально выбранной
частоты», даташит) — не на весь коридор, поэтому в авто-режиме не включаем.

## Аппаратные пункты (вне кода — требуют железа)

### A. ФНЧ гашения гармоник на выходе (самое важное)

**Факт (даташит, таблица характеристик).** Выход ADF4351 близок к меандру:

| Гармоника | Фундаментальный выход VCO | Делёный выход (RFDIV>1, т.е. <2.2 ГГц) |
|---|---|---|
| 2-я | −19 dBc | −20 dBc |
| 3-я | −13 dBc | **−10 dBc** |

Analog в circuit note **CN-0174** (ADF4351+ADL5375) рекомендует ФНЧ:
**5-й порядок ниже 1.25 ГГц, 3-й порядок 1.25–2.8 ГГц, выше 2.8 ГГц не нужен**;
чтобы 3-ю гармонику увести ниже −30 dBc, нужно ~20 дБ подавления (Чебышёв).
Практика [BATC](https://wiki.batc.org.uk/LO_filters) подтверждает для 146/437 МГц.
**Без ФНЧ «импульсы на каждый МГц» дублируются на 2f и 3f**, а PA их усилит —
поэтому ФНЧ ставится **до** усилителя.

### B. Направленный ответвитель + детектор мощности → замкнутая АРУ

**Факт.** Ровный уровень по полосе реально держит замкнутая петля ALC; Hellmich
отмечает, что именно коррекция уровня — самая медленная часть из-за узкой полосы
петли ([mariohellmich.de](https://www.mariohellmich.de/projects/sig-gen/sig-gen.html)).
Разомкнутая таблица (пункт «Выравнивание» выше) плывёт от температуры/нагрузки.

**Что нужно.** Ответвитель после PA → логарифмический детектор (например
AD8317/AD8318, 1 МГц–8 ГГц) → в АЦП ESP32 → подстройка PE43702 в петле.
Нюанс: встроенный АЦП ESP32 нелинеен/шумит — нужна линеаризация/усреднение либо
внешний АЦП.

### C. Терминация и порядок тракта

**Факт (даташит).** Выход рассчитан на 50 Ω, но обязательно через ac-coupling;
неиспользуемый комплементарный/AUX выход **терминировать 50 Ω** — иначе спуры
(в т.ч. на ½f, замер dd1us). Порядок кондуктивного тракта:

```
ADF4351 → ФНЧ (A) → PA → ответвитель → детектор (B) → PE43702 → нагрузка 50 Ω / экран
```

Излучение в эфир свипом = глушилка; тракт замыкается на нагрузку/экран
(см. [compliance.md](compliance.md)).

## Про контроллер (перепроверено)

**Raspberry Pi 5 в тракт управления синтезатором не ставить.** GPIO у неё на
чипе RP1 через PCIe (+1–3 мкс на переключение), обычный Linux даёт всплески
задержек >9 мс, даже PREEMPT_RT — 45–225 мкс ([arXiv 2604.19275](https://arxiv.org/html/2604.19275v1)).
ESP32 с аппаратными таймерами/FreeRTOS детерминирован на порядки лучше и уже
не является узким местом. RPi5 осмысленна лишь как headless-«мозг» вместо
ноутбука (UI/логи/сеть), но не как то, что тактирует SPI.

## Апгрейд синтезатора (если нужна µs-агильность)

TI **LMX2594**: калибровка VCO <20 мкс, аппаратный генератор рампы/чирпа,
FOM −236 dBc/Гц против ~−100 у ADF4351 ([TI](https://www.ti.com/product/LMX2594)).
Смена чипа, не тюнинг; для текущих задач ADF4351 достаточно.
