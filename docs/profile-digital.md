# Профиль: «Цифровой» режим

**Версия:** финальная
**Дата:** 2026-10-16
**Статус:** спецификация закрыта. Хост, UI и NIOS-защёлка `0x65` внесены отдельным путём (`digital`). Умная и обычная атаки не менялись. Quartus не гонялся: в сборку добавлены исходники, образ на плате — после `build_bladerf.sh -b bladeRF-micro -s A4 -r legion`.

Третий режим, отдельно от «Умной атаки» и «Обычной атаки». Этот файл их не описывает и их код не меняет.

---

## 1. Назначение

«Цифровой» режим — третий режим системы наряду с «Умной атакой» (DRFM на плате) и «Обычной атакой» (синтез на ПК).

**Суть:** оператор задаёт один или несколько коридоров, система рассчитывает профили частот, заливает их в FPGA, плата скачет по профилям с точностью до сэмпла и передаёт на каждой частоте выбранный тип сигнала. Цель — обойти коридор быстрее, чем ELRS сменит частоту (250 Гц = 4 мс, 500 Гц = 2 мс).

---

## 2. Входные параметры

**2.1. Коридоры**

- Количество: любое (1, 2, 3, … N).
- Ширина каждого коридора: не более 56 МГц.
- Перекрытие разрешено.
- Формат: `(начало, конец)` в МГц.
- Приоритет задаётся оператором для каждого коридора.

**2.2. Ширина профиля (окно)**

- Закрытый шаг по умолчанию: 7 МГц.
- Оператор или профиль подавления может задать 3.5 или 1.75 МГц — мельче сетка, больше N, цикл дольше. Уже шаг не ускоряет обход.
- Шаг задаёт и расстояние между центрами, и полосу аналогового фильтра TX (кроме тона: там полоса оператора, по умолчанию 0.5 МГц).

**2.3. Режим обхода**

| Режим | Описание |
|---|---|
| Последовательный | Профили проходятся по порядку: 1 → 2 → 3 → … → N → 1 |
| Случайный | На каждом шаге выбирается случайный коридор (с учётом приоритета), внутри — случайный профиль |
| Статичный | Работа только в одном выбранном коридоре, обход внутри него |

**2.4. Тип сигнала на каждой частоте**

Выбирается один раз при запуске. Для смены типа — остановка и повторный запуск.

| Тип | Описание |
|---|---|
| Пила | Линейный пилообразный сигнал в полосе окна |
| Чирп | Линейный up-chirp или down-chirp в полосе окна |
| Гауссов шум | Белый шум с нормальным распределением, полоса окна |
| Тон | Узкополосный тон в центре профиля |
| FM + случайная фаза | ЧМ-сигнал в полосе окна, начальная фаза случайна на каждом шаге |

**2.5. Профиль подавления**

Оператор выбирает пресет цели. Система берёт его dwell и ширину окна, считает `N = ceil((конец−начало) / ширина)` и цикл. Ручное переопределение ширины и dwell — режим «Пользовательский».

| Профиль | Dwell | Окно по умолчанию | Откуда dwell |
|---|---|---|---|
| ELRS 500 Гц | 2 мс | 7 МГц | закрытая спека |
| ELRS 250 Гц | 4 мс | 7 МГц | закрытая спека |
| ELRS 150 Гц | 1/150 с | 7 МГц | период пакета |
| ELRS 50 Гц | 20 мс | 3.5 МГц | период 20 мс; бюджет позволяет мельче сетку |
| Crossfire 868 150 Гц | 1/150 с | 7 МГц | `fpga_control` `crossfire_fsk` |
| Crossfire 868 50 Гц | 20 мс | 7 МГц | `fpga_control` `crossfire_lora` |
| Пользовательский | ввод | ввод | оператор |

Crossfire 915 в дереве нет — пресета нет. Сетка ELRS 2.4 в репозитории — 1 МГц, не 500 кГц. «Кругов за dwell» в UI — это `floor(dwell / цикл)`, арифметика, не эфир.

## 3. Расчёт профилей

**3.1. Для одного коридора**

1. `N = ceil((конец − начало) / W)`, `W` — ширина окна (по умолчанию 7 МГц).
2. Частоты: `начало + W/2 + i × W`, где `i = 0..N−1`.

Пример при W = 7 МГц: коридор 2400–2456 МГц → 8 окон: 2403.5 … 2452.5.
При W = 3.5 МГц тот же коридор → 16 окон: 2401.75 … 2454.25.

**3.2. Для нескольких коридоров**

- Для каждого коридора — свой список частот.
- Все списки объединяются в общий пул профилей.
- При перекрытии одинаковые частоты схлопываются: одна запись, приоритет — максимум.
- Профили нумеруются сквозняком после схлопывания. 257-я запись — отказ при старте, не усечение.

**3.3. Ограничение аппаратных слотов**

- AD9361 имеет 8 аппаратных профилей для TX (20 мкс).
- В слоты попадают не первые 8 по порядку пула, а 8 с наибольшим приоритетом коридора (при равенстве — меньший индекс).
- Остальные — память NIOS, 80–100 мкс. Лимит ключей `nios_profile` — 256 (0…255). 257-й хост отвергает.
- Перекрытие схлопывается. Одинаковый герц не обходится дважды.

---

## 4. Тайминг: обгон ELRS

**4.1. Целевые параметры**

- ELRS 250 Гц: dwell = 4 мс.
- ELRS 500 Гц: dwell = 2 мс.
- Коридор должен обходиться быстрее dwell.

**4.2. Бюджет времени**

| Число профилей | Аппаратные слоты | NIOS-подгрузка | Полный обход |
|---|---|---|---|
| 8 | 8 × 20 мкс | 0 | 160 мкс |
| 16 | 8 × 20 мкс | 8 × 100 мкс | 960 мкс |
| 32 | 8 × 20 мкс | 24 × 100 мкс | 2560 мкс |
| 56 | 8 × 20 мкс | 48 × 100 мкс | 4960 мкс |

**4.3. Условие обгона (арифметика, не эфир)**

Автонастройка считает допустимый цикл = dwell / 4. Это запас оператора, не замер.

- ELRS 250 Гц: обход ≤ 4 мс → до 32 профилей (2560 мкс). Запас 4×: 160 мкс ≤ 1000 мкс.
- ELRS 500 Гц: обход ≤ 2 мс → до 16 профилей (960 мкс). Запас 4×: 160 мкс ≤ 500 мкс, 960 мкс не влезает.

**4.4. Что это значит по коридорам**

- 1 коридор 56 МГц = 8 профилей → 160 мкс → обгоняет и 250, и 500 Гц.
- 2 коридора по 56 МГц = 16 профилей → 960 мкс → обгоняет 250 Гц, обгоняет 500 Гц.
- 4 коридора по 56 МГц = 32 профиля → 2560 мкс → обгоняет 250 Гц, не обгоняет 500 Гц.

## 5. Логика работы

**5.1. Подготовка (один раз)**

1. Хост принимает коридоры, профиль подавления (или ручные W и dwell), режим обхода, тип сигнала.
2. Рассчитывает список частот для каждого коридора.
3. Для каждой частоты: `bladerf_set_frequency` + `bladerf_get_quick_tune` (~6 мс на частоту). Ошибка снимка — этот ключ не в пуле быстрых; шаг для него ~6 мс, обгон ELRS для него не считается.
4. Сохраняет профили в `digital_tunes` (не `pairs` умной атаки).
5. В слоты AD9361 (`schedule_retune(NOW)`) — до 8 с высшим приоритетом.
6. Остальные — ключи NIOS, подгрузка при шаге.

**5.2. Цикл работы**

1. Хост формирует очередь `schedule_retune` на 10–15 шагов вперёд.
2. FPGA выполняет перестройку с точностью до сэмпла.
3. На каждой частоте передаётся выбранный тип сигнала.
4. Очередь пополняется по мере выполнения.

**5.3. Синхронизация**

- Общая временная шкала для всех коридоров.
- Все перестройки планируются по timestamp в сэмплах TX.
- Шкала — счётчик tamer на `fs` (на этом образе 34 МГц, `pll_sclk` 68 МГц). Это не внешние 10 МГц.

**5.4. Режимы обхода**

Последовательный: профиль 1 → 2 → 3 → … → N → 1 → 2 → …

Случайный (с приоритетом): вес коридора = его приоритет, нормировка на сумму; внутри коридора профиль равномерно.

Статичный: работа только в выбранном коридоре, профили по кругу.

## 6. Генерация сигнала

| Тип | Параметры |
|---|---|
| Пила | Период пилы — оператор. Девиация — ширина окна. |
| Чирп | Направление (up/down) — оператор. Девиация — ширина окна. |
| Гауссов шум | Полоса — ширина окна. Мощность — оператор, ≤ 0.9 шкалы ЦАП. |
| Тон | Частота — центр профиля. Ширина — оператор (по умолчанию 0.5 МГц). |
| FM + случайная фаза | Девиация — ширина окна. Начальная фаза — случайна на каждом шаге. |

Амплитуда ≤ 0.9 — тот же потолок ЦАП, что `WAVE_AMP_MAX` / `LEGION_LB_AMP_Q15` (29491). Не 100% шкалы.

Смена типа сигнала — только при остановке и повторном запуске.

## 7. Ограничения

| Параметр | Значение | Причина |
|---|---|---|
| Максимальная ширина коридора | 56 МГц | Аналоговый фильтр AD9361 |
| Ширина профиля | 7 / 3.5 / 1.75 МГц | 7 — закрытый шаг; уже — только если задано |

| Время переключения (аппаратный слот) | 15–20 мкс | Fast Lock |

| Число коридоров | Любое | Ограничено памятью хоста |
| Обгон ELRS 250 Гц | до 32 профилей | 2560 мкс < 4000 мкс |
| Обгон ELRS 500 Гц | до 16 профилей | 960 мкс < 2000 мкс |

## 8. Что даёт «Цифровой» режим

Плюсы:

- Быстрая перестройка (микросекунды вместо 6 мс).
- Гибкость: любое число коридоров, приоритеты, режимы обхода.
- Разные типы сигнала под разные задачи.
- Обгон ELRS 250 Гц и 500 Гц при разумном числе профилей.

Минусы:

- Полоса профиля 7 МГц = плотность мощности ниже узкой полки.
- При > 8 профилях — динамическая загрузка из NIOS, замедление.
- При > 32 профилях не обгоняет ELRS 500 Гц.
- Не покрывает всю сетку ELRS 2.4 (80 МГц) одним трактом.

---

## 9. Фиксация

- Коридоров — любое число, перекрытие разрешено.
- Приоритеты — задаются оператором.
- Ширина окна — 7 МГц по умолчанию; 3.5 / 1.75 по пресету или вручную.
- Режимы — последовательный, случайный, статичный.
- Сигналы — пила, чирп, шум, тон, FM+фаза.
- Смена сигнала — только через стоп/старт.
- Синхронизация — общая временная шкала TX (timestamp в сэмплах).

## 10. Что сделано на хосте и в FPGA

### 10.1. Три режима не смешиваются

| Режим | Кто бьёт | Путь |
|---|---|---|
| Умная атака | DRFM на плате | `smart56.py` → `set_live_drfm` + `MODE_LB_ALWAYS` + hop LUT 0..7 |
| Обычная атака | синтез на ПК | `hostTxWave` / cognitive, не `digital` |
| Цифровой | хост-волна + fastlock TX | `digital.py` → `capture_one` / `schedule_one` / `MODE_PASS` |

Цифровой не вызывает `smart56`, `set_live_drfm`, `hostTxWave`, `detectFromBins`. Умная не читает `digital_tunes`.

### 10.2. Хост

1. Берёт профиль подавления (dwell, ширина). Считает пул: `N = ceil((конец−начало)/W)`, частоты `начало + W/2 + i·W`.
2. Перекрытие схлопывает: одна частота, больший приоритет.
3. Быстрые слоты — по убыванию приоритета, не по порядку пула.
4. Обход: последовательный / случайный (коридор ∝ приоритет, внутри равномерно) / статичный (один коридор).
5. Волна один раз на старт: пила, чирп, шум, тон (центр, полоса аналога по умолчанию 0.5 МГц), FM на ширину окна + новая фаза на шаге.
6. Пишет `0x65=1`, `SCAN=0`, hop autonomous=0, mux `MODE_PASS`. `FpgaBridge` закрывается — USB отдаётся стриму (не «хост перестал читать»).
7. `configure(..., tx_only=True)`: RX не поднимается. `set_frequency` + `get_quick_tune` только TX.
8. `schedule_retune(NOW)` для профилей с `hw` (до 8).
9. Очередь 12 шагов вперёд (лимит NIOS — 16). Пополнение в цикле. Стрим TX: 32 буфера × 8192. Пустая очередь — note. Срыв USB — очередь снята, TX выкл, цикл стоп. Кабель выдернули при живом PASS — mux не глушит (WD PASS не читает).
10. Метка — `bladerf_get_timestamp(TX)`. RX-шкала не используется.
11. Поток `SC16_Q11_META`. Смена типа — только стоп/старт.
12. Стоп / DISARM хоста: `cancel_scheduled_retunes(TX)`, `enable_tx(False)`, `0x65=0`, `disarm()`. Умная атака снова владеет hop LUT. `MODE_PASS` не смотрит watchdog — при обрыве USB хост больше не выключает TX.

### 10.3. Что добавлено в сборку FPGA

Нового hop-автомата и генератора волн в HDL нет. Это было бы выдумкой: перестройка уже есть в `pkt_retune2` + time tamer, волна идёт с хоста через `MODE_PASS`.

Нужно было одно — развязка. Иначе каждый `schedule_retune` TX звал `legion_hop_mute_arm` / `legion_hop_commit_lo` и глушил хост-волну, а leftover hop LUT умной атаки мог сдвинуть сетку.

| Файл | Что |
|---|---|
| `LEGION_REG_DIGITAL` `0x65` | NIOS-защёлка, bit0. HDL не декодирует (`when others`). |
| `legion_cmds.c` | Вкл: SCAN снят, hop autonomous снят, CTRL в HDL = PASS без `air_down`. `legion_work` не ходит в walker и hop LUT. DISARM снимает защёлку. |
| `pkt_retune2.c` | При защёлке: только `adi_fastlock_load/recall`. Mute и LUT умной атаки не трогает. |
| Карта | `legion_pkg.vhd`, `legion_cmds.h`, `legion_fpga.py` — зеркало `0x65`. |

На плате это появится после пересборки NIOS/Quartus. Без нового `.rbf` хост всё равно ставит `MODE_PASS`, но mute в `pkt_retune2` останется старым.

### 10.4. Чего в FPGA нет и не будет

- Генератор пилы/чирпа/шума/тона/FM в BRAM. Волна — USB SC16.
- Вторая hop LUT на 256 профилей. Профили — `fastlocks_tx[256]` Nuand.
- Внешние 10 МГц как шкала. Шкала — tamer TX на 34 МГц.
- Пересборка под 56 MSPS. Оцифровка этого образа — 34 МГц.

## 11. Автонастройка N

1. Оператор выбирает профиль или «Пользовательский».
2. Dwell пресета (или ввод). Допустимый цикл = dwell / 4.
3. Ширина — из пресета, если оператор не переопределил.
4. `N` и цикл считаются от коридоров и ширины. Уже ширина → больше N → дольше цикл. Система не подменяет 7 МГц на 3.5 сама, кроме пресета ELRS 50 Гц.
5. UI/CLI показывают N, ширину, цикл, бюджет, влезает/нет, кругов за dwell.
6. Альтернативы 7 / 3.5 / 1.75 считаются рядом (`alts`), выбор остаётся за оператором.

Пример: ELRS 250 Гц, коридор 56 МГц, W = 7 МГц → N = 8, цикл 160 мкс, бюджет 1000 мкс, 25 кругов (расчёт). 16×3.5 МГц = 960 мкс тоже влезает в 1000 мкс — если оператор так задал.

## 12. Что сделано на хосте / чего нет без прошивки

Сделано без новой `.rbf`:

- Схлопывание перекрытий (больший приоритет).
- Обновление `fastlocks_tx[]` каждые 15 мин (`--digital-refresh-s`, 0 = выкл).
- Стрим TX: 32 буфера × 8192.
- Срыв USB при живом процессе: TX выкл, цикл стоп.
- Note — JSON stdout → журнал кино (шаг, очередь, срыв).
- 257-й профиль: отказ при старте, не усечение.

Не делается без прошивки / датчиков (не выдумывалось):

- Генератор волн в BRAM.
- Watchdog в `MODE_PASS`: волна с USB, регистры не пинаются — WD сорвал бы и живой поток.
- PA / КСВ / 40 Вт.
- Датчик температуры.
- Crossfire 915.
- Прошивка `.rbf` и эфир.
