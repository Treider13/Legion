# LEGION — «включили сканер → нашлось → моментально на SDR → на усилитель»

Снимок: `c213041`. Код и прошивку этот документ не меняет.

Уточнение оператора: задали параметры, **включили сканер**, сигнал
нашёлся и **моментально** ушёл на SDR, с SDR на усилитель. Антенна
сканера на **RX1**. Усилитель указан тоже на **RX1**. Ниже это сведено
с разъёмами платы, с HDL/NIOS и с кнопками UI. Без «потом»: пункт либо
обязателен для этого круга, либо замыслом не обещан.

Связанные разборы того же снимка:

- [analysis-legion-look-window.md](analysis-legion-look-window.md) —
  «нашлась 2450 → на усилитель 2445…2455»;
- [analysis-legion-us-path.md](analysis-legion-us-path.md) — бюджет
  гейта и форумы Nuand;
- [analysis-legion-intent-complete.md](analysis-legion-intent-complete.md) —
  U/R/T и приёмка.

---

## 0. Закрытое определение круга

| Слово оператора | Что это в продукте | Что это не есть |
|---|---|---|
| «задали параметры» | Коридор F1…F2, взгляд, порог, выдержка, 50 Ом, Старт | Host-FFT окно; волна «ЗАШИТЬ» |
| «включили сканер» | Режим **Автоматический перехват** (`scanPattern="fpga"` → `startOnboardIntercept`) | Кнопка **СКАНИРОВАТЬ** в режиме АВТО (`useScanner: true`) |
| «сигнал нашёлся» | `det_active` в текущем взгляде (`I²+Q²`, 16 сэмплов) | Пик Welch на ноутбуке; герц внутри окна |
| «моментально ушёл на SDR» | Тот же bladeRF: RX IQ → FPGA mux `lb_gated` → `dac_streams(0)` → DAC | USB на ноутбук и обратно; второй приёмник; ESP32 |
| «с SDR на усилитель» | SMA **TX1** (micro) / **TX SMA** (x40) → вход PA → 50 Ом | Тот же разъём RX1; ADF4351 |

«На SDR» здесь не «передать в программу на ноутбуке». BladeRF **и есть**
SDR. Моментальный участок — внутри этой платы. Это уже в
`architecture.md` 94–104 и в `fpga/README.md` 6–14.

## 1. Разъёмы: антенна RX1 — да; усилитель на RX1 — нет

### 1.1 Что пишет железо и код (канал 0 = RX1 / TX1)

Nuand именует канал 0 так (`devices_rfic.h` 252–258):

| Макрос | Строка лога | SMA micro | Куда сидит Legion |
|---|---|---|---|
| `BLADERF_CHANNEL_RX(0)` | **RX1** | разъём **RX1** | антенна сканера |
| `BLADERF_CHANNEL_TX(0)` | **TX1** | разъём **TX1** | выход на усилитель |
| `BLADERF_CHANNEL_RX(1)` | RX2 | RX2 | **не** в перехвате |
| `BLADERF_CHANNEL_TX(1)` | TX2 | TX2 | **не** в перехвате |

Доказательства привязки к каналу 0:

- Детектор и FIFO читают **`adc_streams(0)`** (`bladerf-legion.vhd` 1135–1137,
  1194, 1204).
- Mux пишет **`dac_streams(0)`** (1245–1248). Комментарий HDL: «Канал 0 —
  через мукс LEGION; остальные каналы (MIMO) — напрямую от хоста».
- NIOS поднимает и шагает только `BLADERF_CHANNEL_RX(0)` и
  `BLADERF_CHANNEL_TX(0)` (`legion_cmds.c` 128–185, 429–432).
- ENABLE выбирает порт AD9361 по частоте и ставит RFFE MIMO bit канала 0
  (`devices_rfic_cmds.c` 350–453; `RFFE_CONTROL_MIMO_RX_EN_0`).
- `tx_channel_swap` / `rx_channel_swap` в init-params = 0
  (`ad936x_params.c` 221–222): RX1 не меняется местами с RX2.

x40 (LMS): одного RX SMA и одного TX SMA. Каталог: «Усилитель вешается
на **TX SMA**» (`catalog.ts` 25). CONTROL bit1 = RX, bit2 = TX
(`fpga/README.md` 158–162). Без bit2 «mux может считать, а усилитель
ничего не получит».

Текст UI того же снимка: «антенна на **RX SMA** и сама открывает
**TX SMA** на усилитель» (`StartGate.tsx` 237–238).
`architecture.md` 72: «антенна на RX, усилитель на **RF out**».

### 1.2 Если усилитель повешен на RX1

Это не вариант настройки. Это **другой кабель**.

RX1 — вход АЦП. На него смотрит детектор. `dac_streams(0)` уходит в
**другой** разъём (TX1). Если PA стоит на RX1:

- антенна и вход PA делят один SMA (тройник) **или** антенны нет, а PA
  висит на входе приёмника;
- ретрансляция FPGA на TX1 в PA **не попадает**;
- на RX1 PA либо глушит эфир (50 Ом входа PA ≠ антенна), либо гонит
  свой шум/утечку в АЦП — ложный `det_active`;
- TX1 при этом излучает в открытый разъём или в никуда.

Замысел «нашлось → на усилитель» при таком кабеле **физически не
выполняется**, какой бы ни была прошивка. Это не отсрочка и не пункт
ПО: кабель PA обязан быть на **TX1** (micro) / **TX SMA** (x40).
Нагрузка 50 Ом — на **выходе PA**, не вместо этого.

RX2 / TX2 в этот круг не входят. Антенна на RX2: детектор видит тишину
канала 0. PA на TX2: mux канал 1 не кормит (`dac_streams(i) <= host`
для `i≥1`).

### 1.3 Правильная схема (единственная, что соответствует замыслу)

```
антенна ──► RX1 (micro) / RX SMA (x40)
                 │
                 ▼
            AD9361/LMS ADC  →  adc_streams(0)
                 │
                 ├─► детектор I²+Q²  (нашёл = det_active)
                 └─► dcfifo ─► mux lb_gated ─► dac_streams(0)
                                                    │
                                                    ▼
                                            AD9361/LMS DAC
                                                    │
                                                    ▼
усилитель ◄── TX1 (micro) / TX SMA (x40)
                 │
                 ▼
               50 Ом
```

Ноутбук в этом круге нет. USB — kick watchdog и телеметрия.

Самовозбуд: TX и RX на одной частоте. Продукт уже пишет: разнести
антенны, Стоп и watchdog всегда (`StartGate.tsx` 16–22,
`fpgaFastpath.ts` 40–43). PA на TX1 + антенна на RX1 в одном поле —
гейт может держаться утечкой. Это физика, не патч детектора.

## 2. «Включили сканер» — две разные кнопки

В UI слово «сканер» живёт в **двух** режимах. Моментальный круг —
только один.

| Действие оператора | Код | USB в круге? | Моментально на усилитель? |
|---|---|---|---|
| Кино/Старт, путь «Автоматический перехват» | `runSmartStart` path=`auto` → `setScanPattern("fpga")` → `startScan()` → **`startOnboardIntercept`** (`run.ts` 31–38; `store.ts` 3508–3510) | нет | да, если образ/тракт/кабель TX1 живы |
| Вкладка СКАН, режим **АВТО (сканер → ПЕРЕДАТЬ)** | `planSdrWork("auto")`: `useScanner: true` (`modes.ts` 108–118); хост Welch, затем `startTransmit` | **да** | **нет** (сотни µs…мс; `ScanPanel.tsx` 59: «хост-скан — миллисекунды») |
| ПЕРЕДАТЬ при `scanPattern=fpga` | отказ: «ПЕРЕДАТЬ не участвует» (`store.ts` 3687–3695) | — | не этот путь |
| СКАНИРОВАТЬ при живом FPGA ARM | отказ: «хост-скан = мс, не µs» (`store.ts` 3521–3523) | — | смешение запрещено |

`scannerParticipates`: хост-сканер участвует **только** при
`pattern === "auto"` (`modes.ts` 41–44). При `fpga` «глаза — плата».

Следствие, которое закрывает фразу оператора: «включили сканер» в
замысле = **Старт автоматического перехвата**, не кнопка СКАНИРОВАТЬ
режима АВТО. Если включён хост-сканер, «моментально» обещать нельзя —
это другой продукт в том же окне.

После Старта перехвата `startOnboardIntercept` сам делает `stopScan()`
и забирает USB (`store.ts` 1102–1105): хост-FFT в круге быть не должен.

## 3. «Моментально» — что именно, на этом кабеле

Две величины, как раньше. На круге RX1→TX1 они такие:

| Что | Когда | Порядок |
|---|---|---|
| Гейт | Энергия уже в текущем взгляде на **RX1** | 16/fs: 8 мкс @ 2 MSPS; **1.6 мкс @ 10 MSPS** (взгляд 10 → 2445…2455) |
| Сквозь чип | ADC→DAC того же RFIC | EZ 94–102 такта, класс ~5 мкс @ 20 MSPS |
| Обзор коридора | Сменить LO, чтобы «найти» другой взгляд | PLL, не микросекунды |

«Моментально нашлось → на усилитель» = гейт + аналог чипа, **уже
стоя на взгляде**. Не hop 2450→2465. Не USB.

Форум Nuand t=13120: `adc_streams`→`dac_streams` headless обходит USB.
Это тот же класс, плюс гейт по энергии. Host GNU Radio — явно «если
low delay не нужен».

## 4. Каждая рекомендация — против этого круга RX1→нашло→TX1→PA

Колонка отвечает на вопрос оператора: без этого пункта сигнал с
антенны на RX1 **не** окажется на входе усилителя так, как задумано.

| # | Факт | Без этого RX1→TX1→PA «моментально»? |
|---|---|---|
| **Кабель: антенна RX1, PA на TX1** | HDL/NIOS канал 0; `_rfic_chanstr` RX1/TX1; UI «RX SMA / TX SMA» | **Нет.** PA на RX1 не видит `dac_streams` |
| **Режим Автоперехват, не АВТО-сканер** | `fpga` vs `auto` (`modes.ts` 98–118) | **Нет.** Хост-скан = мс, USB в круге |
| **Образ legion, не hosted** | hosted: 0x80 invalid (`gateway.py` 709–713) | Нет mux — TX1 молчит или хост |
| **AIR_PREP / CONTROL RX+TX** | без ENABLE/bit2 TX SMA молчит (`fpga/README.md` 161–162) | Детектор может тикать, PA нет |
| **Взгляд и LO как в look-window** | 10 МГц / 2450 → 2445…2455 на **TX1** | На PA другой канал |
| **`lb_gated`** | NCO — тон на TX1, не эфир с RX1 | PA поёт несущую, не принятый взгляд |
| **U1** валидация до эфира | `_air_enable` до SCAN bounds | Отказной Старт: TX1 может петь без «нашла» |
| **U2** частичный AIR | `air_is_up` в конце | RX1 жив, TX1 нет — или наоборот |
| **U3** честный DISARM | `air_down` игнор | Стоп: PA на TX1 не доказанно тих |
| **U4** hop mute | unmute на fail | PA на чужом LO во время обзора |
| **U5** SCAN readback | чтение = STATUS | Плата смотрит не тот коридор, чем UI |
| **U6–U7** `0,4`→400 мкс | int/parseFloat → 3 с | Для n=1 не меняет гейт; для очереди ломает шаг |
| **R1–R5** FILTER+readback | нет FILTER; 10e6 вне 4x | Взгляд на RX1/TX1 не тот |
| **T1** WD от fs | 10e6 + дефолт 61 → 0.40 с < kick | TX1 гаснет сам среди гейта |
| **T3** CDC det_count x40 | многобит без синка | Ложный UI; гейт mux на `det_active` |
| **T5** убить handoff | `fpgaHandoff` + `fpgaAutoCycle` | Возврат USB = не «моментально» |
| **V1/V3** водопад/герц | `applyLook`; не FFT | Не ломает SMA. Тон на RX1 2447 = тот же TX1-канал |
| **n=1 ARM жив** | walker return | Не дефект: пока энергия на RX1 — TX1 открыт |
| **F3** тишина = нули с valid | иначе LMS держит last | PA на TX1 держит последнюю несущую |
| **L1–L6** образ+STA+libad936x | ping ≠ «встала» | Канала RX1→TX1 нет |
| **E1–E6 сейчас** | SKIP кабеля = ALL PASS | Не доказывают TX1 |
| **50 Ом на выходе PA** | галочка ≠ ваттметр | compliance; без цифры система не принята |
| ADI sync_event / VUnit / ESP32 | не этот круг | Не обязательны |

U4/U6–U7 не отменяет одна стоянка: система обязана ещё обегать коридор
шире взгляда. Для доказательства «моментально на PA» достаточно одной
стоянки и кабеля RX1/TX1.

## 5. Что сделать (один список, этот круг)

Ни SKIP, ни «потом».

### 5.1 Кабель (до любого кода)

1. Антенна (или стимул стенда) — **только RX1** / RX SMA.
2. Вход усилителя — **только TX1** / TX SMA. Не RX1. Не RX2. Не TX2.
3. Выход PA — 50 Ом, мощность записать.
4. RX2 и TX2 — терминаторы 50 Ом (неиспользуемый SMA).
5. Визуально сфотографировать шелкографию **до** приёмки RF.

Пока пункт 2 не выполнен, пункты прошивки не делают «на усилитель».

### 5.2 Кнопка

Старт = **Автоматический перехват** (кино path `auto` / `scanPattern=fpga`).
Не СКАНИРОВАТЬ режима АВТО. Не ПЕРЕДАТЬ. Не Эфир-обход с хост-`tune`.

Параметры до Старта: коридор (для примера 2445…2455), взгляд 10 МГц,
порог >0, выдержка если n>1, галочка 50 Ом.

### 5.3 Красные тесты на `c213041`

Те же U1–U7 / R1 / E2 SKIP, плюс регрессия: Старт перехвата не вызывает
`fpgaHandoff`; `fpgaAutoCycle===false`; хост-скан при ARM отказан.

### 5.4 Код тракта и образ

Как в look-window §5.3–5.4: откаты, FILTER на границе 4x, readback,
WD от fs, Quartus STA≥0, `ping.legion===true`.

### 5.5 Стенд на этих SMA (единственное доказательство фразы)

Кабель стенда: стимул → **RX1**; второй приёмник или анализатор на
**TX1** (или на выход PA в 50 Ом). Нет связи с TX1 = FAIL.

| Шаг | Ожидание |
|---|---|
| Старт перехвата, нет стимула на RX1 | TX1 тишина (нули с каденсом) |
| Стимул в взгляде (2450 или 2447 при взгляде 10) | TX1 несёт тот же канал; задержка порядка §3 (десятки мкс @ 2 MSPS, ~1.6 мкс гейт @ 10 MSPS), не сотни мс |
| Стимул вне взгляда (2430) | TX1 не ретранслирует |
| Стоп / watchdog | TX1 тишина |
| Отказной Старт | TX1 нет несущей |
| Повторить с PA на RX1 (отрицательный контроль) | на входе PA **нет** ретрансляции с mux — доказывает, что «усилитель на RX1» не замысел |
| Хост-скан АВТО вместо перехвата | задержка мс / IQ на ноутбуке — не принимать как этот режим |

Пункт «отрицательный контроль PA на RX1» закрывает формулировку
оператора. Это не опция: иначе можно принять не тот кабель.

## 6. Что нельзя обещать

| Обещание | Почему нет |
|---|---|
| Усилитель на RX1 | TX FPGA сидит на TX1 (`dac_streams(0)`) |
| Антенна на RX2 | Детектор смотрит `adc_streams(0)` = RX1 |
| «СКАНИРОВАТЬ» АВТО = этот круг | `useScanner: true`, USB, миллисекунды |
| Второй ящик «СДР» между находкой и PA | «На SDR» = TX1 той же платы |
| Моментальный hop на соседний взгляд | PLL |
| Hosted FPGA | нет mux 0x80 |

## 7. Прямой ответ

**Да, замысел «параметры → Старт → нашлось → моментально на SDR → на
усилитель» существует и однозначен:** Старт автоматического перехвата;
антенна на **RX1**; FPGA гейтит RX IQ в DAC; с **TX1** на усилитель;
ноутбук не в круге.

**Нет, усилитель на RX1 этому замыслу не принадлежит.** RX1 — вход
сканера. Выход на PA — TX1. Пока кабель PA на RX1, полноценной рабочей
системы нет, даже после исправления U/R/T и сборки образа.

**Нет, на `c213041` системы нет и по остальным причинам:** FILTER/readback,
отказы управления, ALL PASS без SMA, USB-handoff жив, образ/STA не
доказаны. Хост-кнопка «сканер» — другой, миллисекундный путь.

Полный закрытый список = §5 (кабель TX1 + кнопка перехвата + тесты +
код + образ + стенд на RX1/TX1) плюс U1–U7, R1–R5, T1/T3/T5, L1–L6.
Откладывать перенос PA с RX1 на TX1 нельзя: без этого «на усилитель»
не происходит.
